# J3 재전송 전송 세계 계약

동결 worldsim.py와 worldparams.json은 유지한다. recovery_world.py는 동결 사건 처리기를 별도 판으로 보존하고 재전송 원본 범위, T6 보호 모양, 비행별 뒤 패리티 신용을 명시한다. 정책 비용 참조를 import하지 않는다. 세계의 고정 초기 PTO200 ms와 처리2.6 ms, 경주·서버 회계·난수 스트림은 그대로다. 비용 참조의 초기 PTO200.86 ms와 같은 값으로 맞추지 않는다.

재전송 모양 t6_originals_first는 현재 v3 FEC의 응답 전 후속 묶음이다. L'=0, 첫 행동 m>0이면 T'=1이며 m=0이면0이다. 응답 뒤 XOR는 원래 T>0 조건을 유지한다. 원본 범위 all은 전체 k, unacked는 클라이언트가 받은 ACK에서 아직 확인하지 못한 원본 구간이다. 서버의 실제 손실을 아는 missing 범위를 세계의 기본 입력으로 쓰지 않는다. unacked가 비었는데 응답 전 CRYPTO 재전송이 요청되면 미지원 오류로 기록한다. PING을 CRYPTO로 꾸미지 않는다.

비행별 원본 인덱스와 패리티 크기를 기록한다. 이전 비행의 수신 CRYPTO 구간은 전체 완료에 합치지만, FEC 복호에는 현재 비행의 원본과 패리티만 쓴다. credit_scope=flight이면 현재 비행 복구에 부족한 뒤 패리티를 보관한다. 전체 ClientHello가 이전 구간과 합쳐 완성되었다고 미사용 패리티를 곧바로 신용으로 넘기지 않는다. connection은 동결 세계의 동작을 재현하는 진단이다. 선행 패리티는 즉시 신용으로 센다.

타이머는 동결 세계의 사건과 ACK 기반 RTT EWMA·분산·백오프를 쓴다. 실제 quic-go 패킷 번호·암호문·재패킷화를 구현하지 않았으며 원본 인덱스가 같은 CRYPTO 구간을 가리킨다는 근사다. ACK 재무장·빠른 손실·PTO 탐침의 완전한 일치를 주장하지 않는다. 상한에서 손실 없이 강제 종료하지 않고 기존 시간·사건·PTO 상한과 실패 원인을 결과에 남긴다.

경계 시험은 기본 full 및 originals_first가 동결 세계의 같은 seed·마스크에서 모든 기존 필드를 재현하는지, pure-lead 후속 XOR, m0 예외, ACK가 확인한 구간 제외, 복원 구간 이월·비행 격리, 신용≤물리 수신, p0·p1, 두 번째 PTO 백오프를 검사한다. 다음 진단의 기본 비교는 동결 full, 동결 originals_first, T6 all+connection, T6 all+flight, T6 unacked+flight다. 이 구분으로 보호 모양·신용·원본 범위의 영향을 나눠 본다. 성능을 보고 비교나 기본값을 바꾸지 않는다.

진단은 k2·W1280·n_need15, u2 Mbps, RTT50/200 ms, p0.02/0.15의4문맥과 u0·RTT50·p0.15, k1·n_need3·u2·RTT50·p0.15를 사용한다. 행동은 (0,3,1), (0,4,0), (0,0,0), seed31~50, seed·문맥·행동·모드당100연결이다. 이는 후보 고르기 전의 유한 전송 진단으로 총180,000연결이다. 낮은 손실의 조건부 실패 평균은 표본 수와 함께 보고하며, 평균 차이를 이유로 표본이나 문턱을 바꾸지 않는다. 원시 행과 대표 사건 trace를 보존하고 실패율·HCT·전체 바이트·PTO·신용을 따로 집계한다. 전체 W1 비열등이나 실측 검증을 대신하지 않는다.
