# X9 PTO 비율 개발 측정 실행 기록

F29는 [고정 계획](../g3/v33/plans/final_bundle_v1.json)의 X9를 실행한다. quic-go v0.61.0 테스트베드, initial congestion window 32 packet의 development 측정이며 confirmatory가 아니다. 이 문서는 실행 준비 시점의 계획 기록이다. 완료 결과는 [자동 문서](X9_result.md)와 [검산·해석](X9%20결과%20검산과%20해석.md)에 기록했다.

## 조건과 분모

certsize 512 B, RTT 50 ms, uplink 제한 없음, W 1280 B에서 x25519와 X25519MLKEM768을 비교한다. 두 클라이언트 모두 FEC off, tracer 켬, gap 8 ms, timeout 10 s다. group별 expect-k는 각각 1과 2다. 공통 gen33 서버는 FEC on, sealed31, udp-path basic이며 같은 셀의 두 팔에 같은 cert-file과 certsize를 준다. 실제 인증서 DER 크기와 SHA는 수집 자료에서 확인한다.

Bernoulli 손실 5%를 c2s에만 거는 셀과 양방향 각각 5%를 거는 셀을 구분한다. 블록 안 팔 순서는 계획의 Williams 일정대로 교대한다. 방향별 각 그룹에서 105연결씩 61블록을 실행하고 블록마다 앞 5연결을 워밍업으로 따로 보존한다. 분석 분모는 방향별 그룹당 6,100연결, 워밍업 제외 수는 305연결이다. 전체 계획은 244단위, 25,620연결이다. 이 수는 계획값이며 완료 연결 수가 아니다.

주 PTO 사건은 `observation.pto_count >= 1`, 보조 사건은 `initial_datagrams > first_flight_datagrams + 1`이다. 필드 누락과 두 정의의 불일치를 따로 센다. 주 정의의 유효 분모가 방향별 그룹당 6,095 미만이면 기준 실패다. 비율 차이는 MLKEM에서 x25519를 뺀 값이며 짝 블록 차이의 95% 구간을 보고한다. HCT 평균·p99와 실패율도 함께 낸다. 실패 HCT는 계획의 timeout 처리와 성공만의 통계를 구분한다.

## 검정력과 해석 범위

[계획 설명](../g3/v33/plans/final_bundle_v1.md)의 검정력 계산은 기저율 미확인 상태에서 Bernoulli 분산 상한 0.25를 쓴 독립 비율 정규근사다. 양측 유의수준 0.05, 목표 검정력 0.8에서 차이 1.5 %p의 필요 표본은 그룹당 17,442, 차이 3 %p는 4,361이다. 계획 분모 6,100에서의 근사 검정력은 각각 0.381033, 0.912075다. 실제 블록 상관과 누락은 이 계산에 들어 있지 않다. 고정한 블록 수와 기준을 유지한다.

원 측정은 qhct.go genCert의 자체 서명 P-256으로 보이며 DER 길이는 재지 않았고 qamp 하한 512 B를 썼다. 옛 표는 손실 0.5~5% 균일·버스트를 합친 값이라 이 5% 조건과 같은 양이 아니다. 분모가 확인되지 않은 옛 PTO 비율과 z값은 근거로 인용하지 않는다. 차이를 확인하지 못한 결과를 가설 기각으로 쓰지 않는다.

완료 뒤 쓸 문장 틀은 "quic-go v0.61.0 테스트베드, initial congestion window 32 packet, RTT 50 ms, 손실 5%(방향)에서 두 group의 PTO 사건 비율 차이(MLKEM-x25519)는 d %p [L, U]였다. 워밍업을 제외한 유효 분모는 그룹별 n이며 development 결과다"다. 값과 분모는 검산한 결과에서만 채운다. 변경보고와 덱은 D12 기본값대로 수정하지 않는다.

## 실행과 후속 검증

[Windows launcher](Windows%20측정%20실행기.md)에 과제 X9와 완료된 M1 결과를 전달한다. M1 입력은 `g3/v33/results/v33_dev_M1_final_m1_iter024_20261107.json`이다. 계획 SHA와 계획 커밋, M1 SHA, 동결 바이너리 SHA·srcsha를 실행 전에 대조한다. M1의 환경 표류 진단을 함께 전달하지만 X9에 다른 셀의 A/A 자를 적용하지 않는다.

실행 ID는 `final_x9_iter031_20261107`이다. 원자료와 PEM은 로컬 보존 WSL 경로 `~/v33_runs/final_x9_iter031_20261107/`에 둔다. 실행 명령·전원 상태·PID·heartbeat는 로컬 보존 폴더 `C:/dev/codex_handoff/final/runs/`의 `F29_launch.py`, `F29_receipt.json`, `F29_start_samples.json`에 남긴다. 계획 수의 생성·검증은 같은 폴더의 `F29_prepare.py`와 `F29_prelaunch.json`, 독립 대조는 `F29_independent_plan_verify.py`와 `F29_independent_plan_review.json`이다.

측정 완료 뒤 DONE, devbed 종료, 잠금 해제, launcher 종료 코드와 SHA 목록을 확인한다. 결과 JSON의 방향별 PTO 비율·구간·유효 분모·워밍업·불일치를 원자료와 대조하고, 양방향 셀의 s2c 손실이 실제 tc 출력에 있는지 확인한다. 계획 커밋 시각과 첫 단위 시작 시각, w_bound, 수집 완전성도 확인한다. report-only를 같은 입력으로 두 번 실행해 결과·문서·SHA 목록의 바이트 일치를 검사한다. 자동 X9 결과 문서와 [주장 문서](보고서%20주장과%20정정%20목록.md)의 결과 반영은 그 뒤에 한다. 실제 idle은 D79의 관측 한계로 미확인이다.
