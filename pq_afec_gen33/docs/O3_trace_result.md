# O3 RTT trace 진단과 보류 판정

기존 T2 기능 진단66개 stdout,198연결을 재집계했다. 새 시험15개와 독립 검산이 통과했다. 활성 L1 상태4·Go·세계는 유지했고, 반복47의 기존351개·548개 검사 뒤 관련 소스 해시가 모두 같음을 확인했다.

| 기존 기록의 항목 | 수 |
|---|---:|
| 연결 | 198 |
| path_rtt_valid가 참인 연결 | 162 |
| 나중1-RTT ACK를 기록한 연결 | 162 |
| RTT metric 갱신 | 453 |
| HCT 뒤 RTT metric 갱신 | 162 |
| 수치상 ACK 후보가 하나인 갱신 | 427 |
| 수치상 ACK 후보가 여러 개인 갱신 | 2 |
| 수치상 ACK 후보가 없는 갱신 | 24 |
| Retry callback 근처 갱신 | 24 |
| 현재 O3 입력 계약을 충족한 표본 | 0 |

수치상 후보427개 모두 RTT callback이 수신 패킷 callback보다 먼저 기록됐다. 후보 판정에는 미리 정한1 ms 시각·RTT 차이 범위를 썼다. 소유 패킷이 확인된 표본이라고 부르지 않는다. 같은 번호 공간의 최대 ACK 패킷 번호와 callback 차이가 맞는다는 진단이다.

qlog의 qlogMetricsUpdated()는 바뀐 필드만 기록한다. LatestRTT가 같으면 실제 RTT 갱신이 있어도 현재 rtt_updates 목록에 추가되지 않을 수 있다. 따라서 그 목록 길이를 RTT 표본 수로 쓰면 안 된다. RTT 기록 바로 앞의 수신 패킷을 소유자로 고르는 방법도 이 자료에서 맞지 않는다.

ACK 후보가 없던24개는 모두 Retry callback 근처였다. 고정 quic-go는 Retry 전에 Initial 재전송이 없으면 Retry로 RTT를 갱신하며5 ms 하한을 적용한다. 이 소스 경로와 시간상 일치하지만 현재 기록에는 직접적인 sample kind가 없어 각 표본의 원인을 확정하지 않는다. quic_ack_min_rtt라는 현재 source 문자열만으로 ACK에서 얻은 값이라고 단정할 수 없다.

나중1-RTT 표본의 가능성은 확인했다. HCT 뒤 갱신162개에는 각각 수치상1-RTT ACK 후보가 있었다. T2의 재방문 대기와 기존 feedback 수집 대기가 이미 일부 나중 표본을 담고 있다. 그 존재를 근거로 대기 바이트0이나 ACK delay0을 가정하지 않는다.

클라이언트 trace에는 실제 transport 송신 monotime, metric 소유 패킷, 적용한 ACK delay, 데이터그램별 실제 송신 시각과 대기량이 없다. 별도 relay 기록에는 실제 데이터그램 바이트와 시각이 있지만 시계 원점이 다르고 클라이언트가 사용할 수 있는 입력도 아니다. CRC 대조만으로 ACK 소유권과 큐 부재가 증명되지는 않는다. O3 참조에 넣을 값을 임의로 채우지 않았다.

O3는 blocked로 전환한다. 반복47의 변동4배 여유는 합성2-RTT의69.83~84.11%를1-RTT로 분류했고, 역사 근사 보정도 모든 팔 ±1 ms를 충족하지 못했다. 전체 W1을 통과한 후보나 실제 보정 표본이 없는 상태에서 활성 정책을 바꾸지 않는다.

후속 E25는 T4의 관측 보강이다. 원시 RTT와 ACK·Retry 출처, 소유 패킷, ACK delay, 실제 송신 데이터그램과 큐 근거를 함께 기록한다. Go 정책 거울과 분리된 관측 작업이며 T4·T5·T6를 의존으로 둔다. 보호된 quic-go 소스를 직접 수정하지 않는다.

E26은 E25와 J3의 결과를 이용한 정책 재검토다. 현재 D34 참조와 실패를 보존하고, 새 후보는 평가 전에 따로 고정한다. 서로 겹치는 HCT 등급을 임의로1-RTT로 확정하지 않는 관측·우도 연결, 표본 부재, 같은 W1 일정과0.5 ms 기준, 상태 판본과 G1의 Go 거울을 검증한다. E25·E26은 O3 자체를 의존으로 넣지 않아 재진입 순환을 피한다. 다음 주 과제는 의존이 풀린 O4다.
