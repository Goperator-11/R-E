# T1 고정 인증서 결과

gen33 qamp는 certsize에 맞춘 결정적 ECDSA P-256 인증서를 만들고 `-cert-file`로 같은 PEM을 읽는다. 파일에는 단일 인증서와 PKCS#8 키가 들어 있다. certgen은 기존 파일을 덮지 않으며 잘못된 파일을 새 인증서로 대체하지 않는다. `-dry-run`은 파일을 쓰지 않고 예상 지문을 출력한다. 시작 로그의 CERT_META와 서버 stats의 certificate에 DER 크기·SHA와 파일 SHA를 남긴다.

D22에 따라 인증서 생성 서명에만 RFC 6979를 썼다. TLS에는 원래 ECDSA 키를 전달하므로 handshake별 CertificateVerify 길이 변동은 남는다. 인증서 파일 공유로 서버 first flight의 모든 바이트·시간이 같아졌다고 주장하지 않는다. 고정 seed 키는 개발 시험 재료이며 실제 서비스 키가 아니다. 생성 날짜와 알고리즘 계약은 docs/T1 고정 인증서 계약.md에 있다.

Go148시험·vet·race와 핵심 Python351시험·하위 548개가 통과했다. Go의 정확 길이·동치 시험 26크기에 더해 CLI의 별도 프로세스 56회 생성에서 28크기를 검사했다. 범위 경계와 현재 과거 격자의 2955·4032·6000·7000·8000·9000·10000·12000·14000·16000 B를 포함한다. 같은 입력의 PEM 바이트가 같고 모두 목표 DER 길이에 정확히 맞았다. dry-run·저장·재사용 지문도 같다.

2955·6000·16000 B 파일을 각각 off·buf·on 서버에 공유했다. 실제 9서버의 로그와 최종 stats 지문이 파일과 일치했고 ML-KEM QUIC27연결이 성공했다. 인증서 파일 누락과 다른 목표 길이는 종료 2로 거부됐다. 이 smoke는 기능 검증이며 시간이나 HCT를 성능 결과로 사용하지 않는다.

같은 PC의 수정 전 S4 바이너리를 6회 시작했을 때 DER은 목표 2955에서 2962·2962,6000에서 6008·6007,16000에서 16009·16008 B였다. 새 생성기는 목표값과 정확히 같다. 이전 바이너리와 각 시작 로그를 보존했으며, 이 6개 관측으로 예전 결과의 효과 크기를 추정하지 않는다.

봉인 저널 25개를 읽기 전용으로 다시 계산했다. 406블록 중 334블록에서 서버 인증서 크기가 달랐고 최대 차이는 3 B로 감사를 재현했다. 124800행에 연결별 서버 first flight의 패킷 수·크기가 없고 server_after에 conns 상세도 없었다. 따라서 인증서 차이가 서버 패킷 경계를 넘겼는지는 미확인이다. aggregate server_bytes나 클라이언트 first flight 계수로 서버 패킷 수를 복원하지 않았다.

공유 소스 선언에는 qamp의 인증서 분리·CLI·metadata 변경을 기록했다. 다섯 세대 85파일의 선언 외 변경은 0건이다. Python 정책·공유 모수와 Go 정책 지문은 S4 관문 통과 때와 같다. T1에서는 정책 변경이 없어 W1과 전체 정책 관문을 다시 실행하지 않았다.

활성 빌더 build_gen33.sh가 만드는 qamp에 적용했다. 과거 qserver 진입점 server.go와 동결 gen2·v31 바이너리는 그대로이며 새 cert-file 플래그를 지원하지 않는다. T7은 gen33 공통 서버에 같은 파일을 전달하거나, 동결 서버를 써야 하는 비교의 제한을 명시해야 한다. 원래 봉인 측정은 바꾸지 않았다.
