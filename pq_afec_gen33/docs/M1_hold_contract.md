# M1 보류 복호 계약

이 문서는 M1 후보의 구현 계약이다. 활성 L1과 동결 W0·W1은 별도로 유지한다. 보류 모드는 기본 꺼짐이며 구현 대조와 성능 채택을 구분한다. 단계별 실행 결과는 `g3/v33/validation/M1_stage1`에 보존한다.

## 입력과 기한

지원 범위는 v3 패리티, k=1..4, m=1..4, lead=0..m이다. m=0은 원본만 통과한다. 원본에는 FEC index가 없으므로 패리티의 CRC·길이 목록을 받은 뒤에만 비행에 연결한다. 받은 적 없는 metadata나 미래 도착을 판단에 사용하지 않는다. 기존 최근 원본 캐시는 DCID·CRC·길이로 대조하며 수명은 3초다.

서버의 `-lead-hold`는 기본 꺼짐이다. 켠 개발 실행은 명시적인 `-lead-hold-uplink-kbps` 입력을 받는다. 0은 직렬화 시간 0인 무제한 조건이다. 자동 속도 추정은 하지 않는다. 개발 기본 프로파일은 2000 kbps, margin 1 ms, 비행 TTL 1초다. 결과를 보고 값을 바꾸지 않는다.

첫 유효 패리티 수신 시각을 a, 그 패리티 뒤에 송신될 명목 슬롯들의 바이트 합을 B라고 하면 기한은 `a + ceil(B*8000000/uplink_kbps) ns + margin`이다. 속도 0일 때 직렬화 항은 0이다. 선행 index i 뒤에는 남은 선행, 원본 전체, 뒤 패리티가 온다. 뒤 패리티 index i 뒤에는 남은 뒤 패리티만 온다. 패리티 metadata의 원본별 길이와 실제 받은 패리티 길이를 쓴다. 처음 정한 기한은 새 패킷이 왔다고 연장하거나 줄이지 않는다. 재정렬과 지터 때문에 이 기한은 송신 측 절대 기한과 다를 수 있다. 그 차이를 세계 모형에도 그대로 넣는다.

마지막 원본(index k−1), 첫 뒤 패리티, 기한 중 하나가 관측되면 decision_open이 된다. 이미 캐시에 마지막 원본이 있으면 metadata를 받는 순간 열린다. 이 상태는 영속적이다. 당시 심볼이 부족해도 뒤의 원본·패리티 도착마다 재평가한다. 같은 시각에는 TTL, 내부 기한, 패킷 순으로 처리한다. 패킷이 모두 사라졌으면 비행도 타이머도 생성되지 않는다.

Go는 한 ReadFrom 소유자가 읽기를 담당하고 underlying SetReadDeadline에 내부 기한과 외부 read deadline 중 이른 것을 적용한다. 내부 timeout은 상태 전이를 처리하고 읽기를 계속한다. 외부 deadline은 호출자에게 timeout을 반환한다. 같은 시각이면 외부 deadline의 오류 의미를 유지하되 만료된 내부 상태도 정산한다. SetReadDeadline·SetDeadline·Close와의 경합은 별도 race 시험 대상이다. 이 문장 자체가 구현 완료를 뜻하지 않는다.

## 복구와 반환 순서

선행과 뒤 패리티를 유효한 서로 다른 index별로 보관한다. decision_open이고 도착 원본과 패리티로 k개의 독립 심볼이 확보되면 누락 원본을 복원한다. 뒤 패리티의 index 오름차순을 먼저 고르고 부족분만 선행의 index 오름차순으로 고른다. Cauchy 계수의 실제 index는 바꾸지 않는다. 모든 복원본의 길이와 CRC를 확인한 뒤 한 번에 정산한다.

미사용 보관 패리티는 도착 순서로 먼저 반환한다. 현재 처리 중인 원본이 있으면 그다음 반환하고, 복원 원본은 원본 index 오름차순으로 반환한다. 따라서 이 묶음에서 CH를 완성하는 원본보다 미사용 패리티가 앞선다. 이미 metadata 전에 원본만으로 CH가 완성됐다면 뒤늦게 받은 패리티의 신용을 과거 송신 결정에 소급하지 않는다.

복구에 쓴 패리티는 반환하지 않는다. 그 자리에 원래 길이의 원본을 반환한다. 완료 뒤 늦게 온 실제 원본과 패리티는 새 물리 바이트로 통과시키지만 복구 횟수는 늘리지 않는다. 같은 비행에서 아직 보관 중인 패리티 index의 중복은 버린다. 중복 물리 바이트는 BytesIn에만 들어가며 독립 심볼 수와 held는 늘지 않는다. 충돌 metadata도 현재 입력만 버린다. 기존 비행의 metadata는 덮어쓰지 않는다. CRC 복호 실패는 poison으로 닫고 남은 보관 데이터를 버린다.

## 회계와 수명

BytesIn은 실제 소켓 수신 길이, BytesToStack은 실제 반환 길이, pendingBytes는 반환 예약량이다. 모든 전이 뒤 `BytesToStack + pendingBytes <= BytesIn`을 전역과 연결별로 확인한다. 원본을 저장했다고 BytesIn을 다시 더하지 않는다. 반환 버퍼가 작으면 copy한 길이만 BytesToStack에 더하고 나머지는 truncation 폐기량으로 기록한다. 회계 예약은 원래 전체 길이만큼 해제한다.

비행당 held raw와 symbol 복사 합은 32768 B, pending을 포함한 전체 보류 payload는 8 MiB, 비행 수는 1024로 제한하는 개발 기본값을 둔다. 새 심볼 보관 시 다음 UDP 수신·반환을 위한 65535 B를 남긴다. 최근 원본은 최대 1472 B인 512개로 제한한다. metadata와 Go 객체의 할당 overhead를 payload 계수에 포함하지 않으며 RSS가 8 MiB 이하라고 주장하지 않는다. 이 값들은 성능 최적화 대상이 아니다. Python 기준의 단일 비행 상한 검증과 Go 전체 상한 검증을 구분한다.

기한이 TTL 이상이거나 지원 범위 밖이면 해당 비행은 보류하지 않는 통과 경로를 쓴다. 보관 도중 한도를 넘으면 이미 보관한 데이터를 폐기하고 그 비행의 보류 복구를 닫는다. 현재와 이후 입력은 통과시키며 폐기한 심볼을 재사용하지 않는다. TTL 시각에는 보관분을 정확히 한 번 폐기하고 계수를 해제한다. 완료·폐기 비행의 기록을 recent TTL까지 유지해 같은 flight의 늦은 패리티가 복구를 재개하지 않게 한다. 상한·만료·poison은 서로 다른 계수로 남긴다.

## 기준 구현과 검증

`experiments/v33/hold_decoder.py`는 한 비행의 정수 ns 사건 기준이다. 패킷 식별자는 시험 입력의 원본·패리티 index이며 실제 CRC 파싱을 대체하지 않는다. metadata를 보기 전에는 원본을 즉시 반환하고 최근 캐시만 보관한다. 실제 Go 파서·CRC·GF(256) 복구의 byte equality는 별도 와이어 대조에서 검사한다. 이 모형의 개수 기반 복구만으로 실제 RS 복구를 통과했다고 세지 않는다.

와이어 기준과 비용 모형은 `receive_and_drain`으로 타이머를 입력보다 먼저 처리하고 반환 예약을 비운다. 이때 다음 물리 패킷을 읽기 전의 BytesIn도 보존한다. 낮은 수준의 `receive`, `advance`, `read`는 작은 반환 버퍼와 보관 상태 시험에 사용한다. 실제 read 호출을 늦춘 소비자의 처리 정체는 별도 조건이다.

와이어 고정 fixture는 원본 i의 길이 1200+17*i B, DCID 8 B, SCID 4 B, 패리티 1331 B다. RS symbol은 1331−34−6*k B로 0을 채운다. 원본 길이 밖의 RS padding을 손상시켜도 원본 CRC가 바뀌지 않을 수 있다. CRC 실패 시험은 원본 범위의 복원 데이터를 손상시킨다. 이 fixture가 모든 실제 CID 크기의 전송 상한을 검증하는 것은 아니며 J7은 계속 미채택 상태다.

`experiments/v33/hold_layout.py`는 보류 후보의 별도 비용 모형이다. 현재 활성 `padfec3/layout.py`의 기본값과 정책 결정에는 연결하지 않았다. `before_link`와 `after_link`의 손실 위치를 명시하며, 현재 W0 기본값은 `before_link`에 대응한다. 후보의 정책 연결, 독립 세계 판본, 고정 성능 계획과 비교는 M1의 남은 단계다.

모든 부분집합과 순열은 60개 설정, 700116개 사례를 예상한다. stable case ID, 설정별 예상·실제 개수와 출력 digest를 보존한다. 타이머 경계, 중복, CRC·metadata 충돌, 작은 반환 버퍼, 다중 연결·cap·Close는 별도 사례다. 첫 비행 P_fail, model-world J, 독립 세계 HCT, 실제 개발 측정은 서로 다른 결과로 보고한다. 감사의 약 10 ms와 P_fail 약 0.0004는 완료 기준이며 이번 실행 결과가 아니다.
