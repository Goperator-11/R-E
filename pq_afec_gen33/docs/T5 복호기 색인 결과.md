# T5 복호기 색인 단계 결과

DCID와 연결 계정별 색인, 원본·비행·payload 상한을 구현했다. Go 180개와 vet·race, 핵심 Python351개·하위 548개가 통과했다. ReadFrom700116사례·60설정은 원래 Python 참조와 바이트 및 prefix 회계가 일치했다. T5 전체는 partial이며 UDP OOB·ReadBatch와 A3-14 비행 대기 관측을 이어서 처리한다.

이번 자료는 구현 검증과 개발용 CPU 대조다. 정책 산술 23파일은 T4 관문 당시와 같고, 활성 L1·상태 4와 기본 lead-hold off를 유지했다. 공유 85파일에서 선언하지 않은 차이는 0개다.

| 검사 | 결과 |
|---|---|
| 다른 DCID 비행 1000개와 정상 복구 | 원본 조회 2회, 다른 비행 방문 0회, 복원 1개 |
| 전체·연결별 비행 상한 | 1024개·8개에서 새 비행을 거부하고 기존 기록 유지 |

CPU 대조는 서로 다른 DCID의 비행 1000개, 비행당 k32, 워밍업 원본 512개, 원본 처리 10000회, GOMAXPROCS1 조건이다. 기록 생성 시각을 미래로 고정해 측정 중 TTL로 부하가 줄지 않게 했다. 수정 전은 원본당 10682260.166 ns, 수정 후는 1494.117 ns였다. 각 판본을 한 번씩 실행한 값이며 통계적 성능 판정이나 HCT 결과가 아니다. 새 판본의 연결별 원본 64개 상한도 이 대조에 포함된다. 상세 원자료와 실행 소스는 T5_index_benchmark_v1.json과 t5_index_benchmark_v1.py다.

A3-03의 미관측 DCID parity 무조건 폐기 제안은 위 k1·m1 반례 때문에 적용하지 않았다. 상한이 있는 신규 비행을 허용한다. 원본·비행 상한으로 정상 복구 기회를 잃을 수 있으며 해당 계수를 기록한다. 비행 생성 전 이미 축출된 원본까지 판별하지는 못한다. 출발지별 속도 제한과 암호학적 인증은 이번 구현 범위 밖이다.

첫 세 빌드는 새 시험의 uint16 타입, 가짜 소켓 필드, Close 구현 누락 때문에 실패했다. 네 번째 빌드는 기존 타이머 시험이 불필요한 3초 대기를 검출했다. 기록 정리 heap과 소켓 대기 heap을 나눠 해결했다. 이후 177개 검증과 종료·축출 보강 뒤 180개 검증을 통과했으며 모든 실패 소스를 보존했다. 경계 smoke 첫 실행은 주기 통계 파일을 읽을 때 FileNotFoundError로 중단됐다. 원래 13초 한도 안에서 재조회하게 고친 뒤 같은 연결·거부·만료 기준을 통과했다. 결과를 근거로 문턱이나 손실 일정을 바꾸지 않았다.
