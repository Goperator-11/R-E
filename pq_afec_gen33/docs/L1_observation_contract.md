# L1 첫 비행 관측 계약

2026-11-02 정정: 아래 비교 모드 표의 none은 L1(상태 4)의 HCT 3등급 경로를 검증한 것이다. 지금 활성 정책 v3.3.1-dev(상태 11)에서 C1 회신이 확인되기 전 목적지는 v3.2-dev와 같은 이진 우도·결정을 쓰고, 범주 우도는 c1 경로에서 쓸 수 없는 회신, 곧 회신이 없거나(`source_none`) 잘렸거나(`truncated`) 비어 있는(`sent=0`, `empty`) 연결에만, 결정 문맥이 있을 때 쓴다(`padfec3/learn3.py` `_observe_c1`). 근거 `docs/V33FIX_policy.md`.

L1은 학습 수식, 관측 가능성, 전송 세계를 나눠 검증한다. `experiments/v33/first_flight_observer.py`는 W0의 전송 소스를 수정하지 않고 실제 처리된 사건 기록에서 첫 비행 증거를 만든다. 이 모형은 개발 시뮬레이션이며 qamp의 CRC 와이어 검증을 대신하지 않는다.

## 학습기에 전달하는 정보

학습기는 `src`, `sent`, `lost`, `bitmap`, `trunc` 다섯 필드만 받는다. `bitmap` 순서는 관측 구현을 따른다. Python 관측자 `experiments/v33/first_flight_observer.py`는 입력 송신 목록 순서, Go 클라이언트 `experiments/quicbed/observation.go`는 first flight 원본 전체 다음 parity 전체 순서다(parity 안에서는 선행, 후행). 학습은 `sent`와 `lost` 개수만 쓰므로 이 차이는 정책에 영향이 없고, 위치별 분석을 할 때만 구현 순서를 확인한다. 1은 물리 도착, 0은 충분한 관측 마감까지의 미도착이다. 복구 원본이나 재전송은 첫 비행 도착 수에 들어가지 않는다. 완전한 C1 증거를 쓴 연결에 HCT 우도를 다시 곱하지 않는다.

관측자 core는 송신 목록, 처리된 수신 목록, 피드백 전달 사건을 입력으로 받는다. 송신 목록의 식별자는 중복될 수 없고, 수신 목록의 중복 식별자는 한 번만 센다. 완전한 피드백 목록은 해당 스냅숏까지 수신한 식별자 집합과 같아야 한다. 미래 패킷이나 누락된 수신 항목을 완전한 목록으로 받아들이지 않는다. 참 손실률, 인증서 크기, 세계의 결과 등급, oracle 결과는 core에 전달하지 않는다.

## 비교 모드

| 모드 | 증거 | 해석 |
|---|---|---|
| none | `src=none` | 학습기의 HCT 3등급 경로를 검증한다. |
| c1 | 전달된 완전 수신 스냅숏 | 주 비교다. 회신 부재, 목록 잘림, 수신 버퍼 한도, 관측 마감 때문에 증거가 없으면 none으로 간다. |
| ideal | 충분한 마감까지의 완전 수신 기록 | 정보의 상한을 보는 진단이다. 회신 없이도 전멸을 알며, 잘린 UDP 데이터그램의 물리 도착도 센다. 실제 클라이언트에서 얻을 수 있는 증거라고 주장하지 않는다. |

다른 모드가 같은 정책 버전을 쓰더라도 실행 정체성에는 관측 모드와 모수를 포함한다. 원래 W1 결과는 유지하며, 새 원자료는 별도의 overlay 계약에 묶는다.

## 동결 세계에 덧붙인 근사

W0에는 실제 Handshake 패킷과 C1 메시지가 없다. c1 모드에서는 처음 실제로 도착한 후속 응답 원본 R을 Handshake 대용 사건으로 삼고 그때 수신 목록을 잠근다. Q 복구를 물리 R 도착으로 바꾸지 않는다. 식별자는 `(flight, kind, index)`다. 실제 CRC 바이트, 충돌, 인증, peer/CID 검증은 모형화하지 않는다.

세계가 연결마다 고정한 편도 지연과 첫 비행 송신 완료 시각으로 관측 마감의 하한을 계산한다. 스냅숏이 그보다 빠르면 누락 항목을 손실로 확정하지 않는다. 이 마감 보장은 고정 지연을 쓰는 세계의 가정이다. 실제 배포에서는 지연 상한과 타이머 계측을 검증해야 한다. `arrivals` 배열의 미래 `arrived` 비트나 `initial_failure` 결과는 도착 증거를 만드는 데 쓰지 않는다. 수신 증거는 `trace=True`가 남긴 처리 완료 `server_receive` 사건에서만 온다.

회신 손실 난수는 `seed:connection:v33-c1-feedback-v1`의 독립 스트림이다. 그 확률에는 시나리오의 s2c 손실을 사용하지만, 값 자체는 학습기에 보내지 않는다. 회신은 같은 세계 편도 지연 뒤에 도착한다고 가정한다. 성공 연결에서는 HCT 뒤 200ms까지, 실패 연결에서는 종료 시각까지만 기다린다. 회신의 바이트, 처리 비용, 대기 시간이 물리 HCT나 다음 연결의 시작 시각을 바꾸지는 않는다. 따라서 이 결과는 실제 피드백을 켰을 때의 총비용을 입증하지 않는다. 실제 qamp의 c1 경로도 C1 대기창에 받은 datagram을 정책 입력에 넣지 않는다. 정책 S는 대기 전 `server_bytes_pre_wait`, 정책 RTT는 대기 전 ConnectionStats이고, 대기창까지 센 `server_bytes`와 대기 뒤 RTT(`path_rtt_after_wait_ms`, `path_rtt_after_wait_valid`)는 행에만 남는다. 이 세계의 srv_bytes와 비교할 실측 S는 `server_bytes_pre_wait`다.

c1 모드에서 송신 데이터그램 하나라도 수신 버퍼 한도를 넘으면 연결 전체의 도착 증거를 censored로 둔다. 잘린 UDP 도착을 네트워크 손실로 오인하지 않으려는 처리다. 피드백의 CRC 목록 한도 초과는 별도 `crc_list_truncated`로 기록한다. 원본과 패리티를 합친 목록에서 중복을 제거한 뒤 한도 64를 적용한다. 이는 현재 qamp.go의 `fbCRCCap`과 수신 CRC 저장 순서에 맞춘 값이다.

## C2와 ACK

완전한 수신 스냅숏에서 첫 비행 식별자가 하나도 없으면 all-lost 우도를 적용한다. ideal 모드는 회신이 없어도 이를 확인한다. c1 모드의 회신 없음과 PTO만으로는 전멸을 확정하지 않는다. 첫 원본 일부가 도착하고 모든 서버 응답이 사라진 경우도 같은 관측을 만든다. 이 선택은 `state/DECISIONS_NEEDED.md` D13에 기록했다. 생존 편향이 모두 해결되었다고 쓰지 않으며, 전체 연결을 분모로 회신 누락과 fallback을 보고한다.

`evaluation_only_*` 진단은 완전한 세계 기록으로 C2 휴리스틱의 오판을 검사하는 분석 필드다. worker 요청에 전달하지 않는다. ACK가 없는 데이터그램을 미도착으로 채우는 경로도 두지 않는다. FEC 복구 원본의 ACK와 물리 원본의 ACK를 구분하는 실제 계측은 T4의 범위다.

## 검증

`tests/test_v33_first_flight_observer.py`는 재전송과 복구 분리, 중복 수신, m=0, 전멸, 회신 유실, 잘림, 미래 도착, 잘못된 자료, RTT200 PTO를 검사한다. 부분 원본이 도착했지만 응답이 모두 사라진 반례도 포함한다. 동일 행동과 seed에서 trace 사용 여부와 관측 모드를 바꿔도 세계 결과와 이후 난수 흐름이 같은지 비교한다. 실제 와이어 검증과 새 정책의 전체 W1 벤치는 별도 관문이다.
