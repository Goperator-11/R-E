# O4 현재 k 후보의 W1 재생 계획

현재 k 후보는 기존 L1의 W1 원자료 900실행을 같은 seed31~50, 15시나리오, none·c1·ideal로 재생한다. 각 연결의 현재 ClientHello는 합성 로컬 입력으로 먼저 고정한다. B4는 CRYPTO261 B, 나머지는 1447 B이며 DCID10 B·SCID4 B·토큰 0 B다. 모든 허용 W1200~1452에서 각각 k1·k2인지 먼저 검사한다. 실제 TLS 입력을 수집했다는 뜻은 아니다.

동결 W1의 시나리오·단계·혼합 전체에서 k가 이 값과 같은지 검사한다. 세계가 숨긴 손실률·인증서·RTT를 정책 결정에 전달하지 않는다. 정책에는 고정한 로컬 FirstHello, W·u·c_pkt와 과거 관측 RTT만 준다. 결정 뒤에는 저장된 동일 행동의 관측을 넣는다.

각 결정의 기존 필드 전체, 관측 분류 전체와 마지막 정책 요약을 원자료와 정확히 비교한다. tuple과 list의 JSON 표현만 정규화한다. 실수 허용 오차는 두지 않는다. 후보의 새 metadata는 비교에서 따로 구분한다. 행동이나 사후가 한 번이라도 다르면 그 seed의 재생은 실패이며 그 뒤 관측을 후보 성능으로 사용하지 않는다.

모든 연결에서 행동·관측·마지막 상태가 같을 때만, 동결 세계의 같은 입력·seed·행동에 대한 HCT와 바이트를 그대로 재사용할 수 있다. 이 경우 seed별 HCT 차이는 구조적으로 0이다. 원자료의 SHA, 결과 receipt, 완전한 seed 목록과 요약 재집계를 확인한다. 전후 표는 기존 W1 고정 k 범위의 동등성으로 표시하고 새 세계 실행 또는 실측 개선으로 부르지 않는다. 통계적 개선이나 다른 시나리오에 대한 증거가 아니다.

후보와 의존 소스는 별도 snapshot에 원본 바이트로 복사한다. 실행 전후 전체 해시와 실제 import 경로를 확인한다. 원자료는 읽기만 한다. dry-run은 전체 입력 목록·해시·로컬 k 범위를 확인하고, smoke는 45개 시나리오·모드의 seed31에서 각 단계 첫 4연결을 원자료 순서대로 잘라 쓰지 않고 첫 단계 첫 4연결만 재생한다. full은 중간 생략 없이 전체를 재생한다. 기준과 소스가 바뀌면 별도 계획 판본을 만든다.

W1에는 목적지 이력의 k가 현재 k와 다른 일정이나 W에 따른 재패킷화가 없다. 이 공백은 단위 시험과 실제 T2·T3 입력 검증과 함께 기록하고, 후보별 natural_k를 처리할 정책·세계 평가를 후속 과제로 분리한다. 실제 qamp 입력 훅·expectK·취소·Retry·Go 산술 연결도 별도 후속이며, 이 재생만으로 O4를 완료하거나 후보를 활성화하지 않는다.
