# L3 감시 설계와 개발 평가 계획

2026-11-02 정정: "활성 기준은 L1 상태4"는 당시 사실이고 L3 후보(상태 6)는 채택되지 않았다(`docs/L3_disposition.md`). 지금 활성 정책 v3.3.1-dev(상태 11)는 C1 회신을 본 목적지에서 record_only 진단 팔(`g3/v33/policy_snapshots/L3_record_only_v1`)과 같은 결정(가산 벌점 없음, `arrival_streak`가 0보다 크면 16번째 재평가 보류, β 반응 없음)을 쓰며 CUSUM 감시는 옮기지 않았다. C1 회신이 확인되기 전 목적지는 v3.2-dev와 같은 이진 우도·벌점·재평가를 쓰고, 범주 우도는 c1 경로에서만 쓴다. 근거 `docs/V33FIX_policy.md`.

2026-10-31 작성. 활성 기준은 L1 상태 4다. L2 EPS 후보는 미채택 상태로 보존한다. L1의 3등급 fallback·고정 EPS0.001·현재 관측 RTT를 쓰는 손실 우도는 유지한다. 새 감시 snapshot의 경계로 손실 우도를 바꾸지 않는다. 상태는 6으로 올려 실험 후보 5와도 구분한다. 이전 1~5는 거부한다.

## 결정과 관측의 순서

기존 감시의 가산 ms 벌점은 결정에서 제거한다. 유효 arrivals는 L1처럼 경보·nominal2·shield와 무관하게 한 번 학습한다. 이전 연결에 완전한 c1/ack 증거가 있었으면 다음 결정의 고정 16번째 재평가를 끈다. 잘림·회신 부재·빈 계수는 다음 결정부터 기존 재평가로 돌아간다. 현재 연결의 미래 회신 여부는 사용하지 않는다. KG와 Thompson sampling은 구현하지 않는다.

선택한 최종 행동에 대해 hazard 예측을 순수 계산으로 한 번 적용한 등급 사전 예측을 저장한다. 결정 counter·관측 counter·행동·문맥·전송 입력·경계·기본 q·보정 q·사용 β·C1 준비 상태를 snapshot으로 직렬화한다. 관측에서 한 번 소비하며 맞지 않거나 없는 snapshot은 감시에서 제외하고 사유를 남긴다. 현재 C1 결과로 q를 다시 계산하지 않는다. 상태와 후보 결과는 모든 검증·계산이 성공한 뒤 갱신한다.

감시 라벨은 저장된 결정 RTT와 현재 L1의 grade_cutoffs로 분류한다. 성공했어도 HCT가 늦으면 2R/F이며 실패는 HCT 없이 F로 기록한다. cold 문맥이 없으면 감시하지 않는다. 기존 손실학습의 grade와 새 monitor_grade가 다르면 각각 남긴다. cutoff는 물리 왕복 수 정답이 아니다.

## CUSUM과 비용 보정

3등급 예측을 보존하되 통계는 z=1[2R 또는 F]와 q=q2+qF인 양방향 Bernoulli CUSUM이다. R=2와 0.5, h=5를 사용한다. 갱신은 max(0, S+z*log(R)-log1p((R-1)*q))다. 수치용 q 경계는 1e-6와 1-1e-6으로 고정하며 기록한다. 등급별 완전 categorical 검정이라고 부르지 않는다. 현재 관측 행동만 갱신하고 h 이상이면 그 방향의 경보 episode를 기록한 뒤 두 통계를 0으로 재설정한다. 한 연결·한 행동은 경보 1회로 센다.

행동별 최근 32개 (기본 비1R 예측, z)를 보존한다. 경보가 나면 logit offset β를 정규화된 로지스틱 우도의 MAP로 적합한다. 목적함수의 ridge 항은 4*β²/2이며, β 범위는[-log(4),log(4)]다. 단조 score 방정식을 40회 이분법으로 푼다. q가 바뀐 과거 연결은 각자의 기본 q를 사용한다. 경보 없이 β와 같은 방향의 통계가 0으로 돌아오면 같은 창으로 재적합하되 β의 절대값을 줄이는 방향만 허용한다. 반대 부호로 넘어가려면 반대 경보가 필요하다. 첫 초안의 양방향 모두 0 조건은 각 Bernoulli 관측에서 한쪽 increment가 양수이므로 일반적인 회복 경로가 없었다. 전체 W1 성능 실행 전에 이 논리 오류를 고쳤다. 이 상수들은 성능을 보기 전에 고정한 개발 기본값이며 최적값이라고 주장하지 않는다.

β 반응은 결정 전 연속 8개 완전 도착 증거가 있고 현재 관측도 완전할 때만 허용한다. 그 밖에는 CUSUM 기록만 남긴다. 이 조건은 C1로 p를 먼저 배우라는 검증자 단서의 운영 기본값이며 p의 정확도 보장은 아니다. 미관측 행동이나 오래된 경보로 새 episode를 만들지 않는다.

모형의 1R·2R·실패별 비용 기여 합을 layout에 별도 반환한다. 기존 J 누적 순서와 값은 유지한다. 사후 평균 등급 질량과 비용 기여를 모은 뒤 비1R 질량의 logit에 β를 더한다. 2R/F 안의 비율은 유지한다. 새 확률과 기존 조건부 비용을 곱해 기대비용을 계산한다. β=0일 때는 기존 J를 그대로 사용한다. J에 β를 ms로 더하거나 전체 J에 odds 배율을 곱하지 않는다. 확률 0인 등급에 새 질량을 만들지 않으며 끝점에서는 비용 보정을 하지 않는다. J1 이후의 꼬리 수정도 같은 등급 기여에 들어가야 한다.

## 공통 변화의 제한

최근 32개 전체 관측 안에 실제로 관측된 행동이 2개 이상 있고, 그 행동 모두가 같은 방향의 반응 가능한 새 경보를 마지막 공통 조치 이후 냈을 때 공통 변화로 분류한다. 한 행동만으로 손실 변화와 행동 오류를 식별하지 않는다. 공통 조치에는 현재 연결을 한 번만 사용한다.

공통 변화면 해당 경보에서 새로 적용했던 행동별 β를 각 경보 직전 값으로 되돌리고, 가장 빠른 두 hazard 성분의 합산 odds를 2배로 올리되 합산 질량 0.8을 상한으로 둔다. 이미 0.8 이상이면 낮추지 않는다. 두 그룹 안의 상대 가중은 유지한다. 현재 관측의 C1 우도는 이미 한 번 반영됐고 추가 class 손실 우도는 곱하지 않는다. 새 가중은 다음 결정부터 작용한다. H 집합·prior·격자는 L4에 남긴다.

## 성능을 보기 전 고정할 평가

세계·시나리오·20개 seed31~50·19참조·문턱을 유지한다. 새 raw가 모두 끝난 뒤 전체 행동 합집합을 고정하고 N131072·seed850001로 한 묶음에서 평가한다. L1의 별도 정밀화 MC 폭을 새 후보에 섞지 않는다.

최종 후보는 none/c1/ideal 각 300실행이다. C1 진단은 (1) 옛 벌점만 제거하고 재평가 유지, (2) 재평가 제거와 새 감시 기록만, (3) β 반응까지, 공통 hazard 반응 제외의 세 팔을 각 300실행한다. 최종 C1과 세 진단의 단계별 차이로 기여를 분리한다. 진단 팔을 결과를 보고 대체 후보로 채택하지 않는다. 원래 L1의 900실행과 v31/v32의 600실행을 비교 기준으로 보존한다.

채택에는 none·c1 각각 L1 대비 15셀과 c1-v31의 15셀 비열등 상한 0.5 ms/연결, c1 B1 후회 0.1 미만·B2 후회 0.5 미만, B1 경보율 1000결정당 1 미만, 아래 오류 주입 감지 기준이 필요하다. c1-v32·none-legacy·ideal은 모두 보고한다. 전후 비교에서 적어도 한 셀의 비용 감소 근거도 필요하다. 실패·미확정은 통과가 아니며 셀 간 상쇄는 허용하지 않는다. B4 바이트·B5 적응·p 편향 등 기존 W1 지표도 그대로 보고한다.

고정 q 감시 시험은 성능 벤치와 구분한다. q=0.03·0.06·0.42에서 각 200000연결의 양방향 경보율을 seed920001부터 고정된 별도 난수열로 잰다. 모형 오류 주입은 비1R 확률 0.03에서 0.66으로, 각 250회 독립 seed910001부터 진행한다. 정상 500결정 뒤 변화 200결정, 지연은 변화 뒤 첫 상향 경보까지이며 미감지는 censor다. 카드의 15결정은 전체 250회 중 미감지를 무한대로 포함한 중앙값으로 사전 해석한다. 감지율과 지연분포를 함께 보고하며 모든 표본 경로의 15결정 보장은 주장하지 않는다. W1 폐루프의 B1 오경보와 이 고정 q 시험을 혼동하지 않는다.

기존 raised 목록은 새 episode만 담는다. guard_alarm 같은 옛 64결정 차단 필드는 정책 반응에 사용하지 않으며 새 monitor 진단을 별도로 둔다. g_resid/g_common은 기존 잔차 진단을 보존하지만 관측에서 옛 guard_check를 호출하지 않는다. 남아 있는 g_alarm 값은 legacy_skip_reason 진단만 만들며 실제 skip이나 점수를 바꾸지 않는다. guard_off 등 과거 worker 변형의 의미를 바꾸지 않는다. 새 수집기는 동결 후보의 명시적 mode를 검증한다. Python 후보와 Go는 아직 동일 구현이 아니며 Go 반영은 G1이다.
