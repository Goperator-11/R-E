# J7 parity 길이와 수신 상한

2026-11-02 정정: "활성 Python 기준은 L1 상태4"는 당시 사실이다. 지금 활성 정책은 v3.3.1-dev(상태 11)이고, C1 회신이 확인되기 전 목적지는 v3.2-dev와 같은 이진 우도·결정을, 범주 우도는 c1 경로에서만 쓴다. 1452 B parity 상한은 J7의 46 B 기하가 아니라 지금의 W+39+6k B 기하로 적용됐으므로, parity 후보가 남는 W 상한은 k1·2·3·4에서 1407·1401·1395·1389 B다. 근거 `docs/v3.3.1 활성 정책 수정.md` 1·5절.

활성 Python 기준은 L1 상태 4다. L5 상태 9 후보는 보존돼 있으며 J7에 합치지 않는다. J7은 parity 본문 padding, 수신 가능한 후보, 파싱 실패 계측을 다룬다.

parity 길이는 W+46+6k B로 고정한다. 헤더와 PFEC 메타데이터의 길이는 22+len(DCID)+len(SCID)+6k B이므로, 선언된 본문 끝에 24-len(DCID)-len(SCID)개의 0을 붙인다. 현재 클라이언트의 SCID4와 DCID0~20을 포함한다. CID 각각 20 B 이하이고 합이 24 B 이하인 조합만 지원한다. 그 밖의 조합은 parity 생성을 거부하고 원본 전송을 유지한다. 빈 parity를 송신 성공으로 세지 않는다.

정책과 생성기의 parity 상한은 1452 B다. k1·2·3·4에서 parity를 붙일 수 있는 W 상한은 1400·1394·1388·1382 B다. 원본 Initial의 1452 B 상한과 구분한다. 강제 행동이 이 상한을 넘겨도 송신기는 parity를 거부하고 오류 계수를 남긴다.

parseFecBlock이 거부한 패킷 중, 읽을 수 있는 Initial 헤더와 token length0 뒤의 고정 PFEC 본문 시작 위치에 매직이 남은 패킷을 fec_parse_fail로 센다. 선언 길이보다 짧은 수신도 포함한다. 임의 위치의 문자열 검색은 쓰지 않는다. off 모드는 기존대로 PFEC 분류를 하지 않으므로 이 계수는 0이다. 이 계수 하나로 커널 잘림, 잘못된 버전, 손상된 메타데이터를 식별하지 않는다.

수정 전 Go 빌드와 전체 대조 관문을 먼저 기록한다. Go는 기존 상태 3·1비트 우도를 사용하고 Python L1은 상태 4·3등급 및 도착 우도를 사용한다. Python의 3등급 EPS는 0.001이며 남아 있는 legacy EPS 상수는 0.01이다. 이 차이는 J7 크기 변경 전에 존재한다. 기준 벡터의 stale 판정이나 학습 궤적 불일치를 숨기지 않고, 일부 산술만 맞았다는 이유로 전체 관문을 PASS로 기록하지 않는다. 전체 관문을 충족할 수 없는 범위는 독립 후속 과제에 남긴다.

시험은 CID 길이 전 범위, 선언 본문 padding, 원본·심벌 보존, 지원하지 않는 CID와 크기 거부, 파싱 실패 계수의 양성·음성 대조, Python·Go 후보 상한을 확인한다. 기존 정적 수치가 39 B 형식을 전제하면 입력과 비교 허용치를 유지한 채 Python 기준 산술로 새 기대값을 먼저 생성해 보존한다. Go 결과를 보고 기대값을 맞추지 않는다. 이전 wire golden과 고정 원자료는 보존한다.

Python 정책 수정의 전체 W1 검증도 필요하다. 기존 39 B 세계는 바꾸지 않으며,46 B 개발 프로필의 결과를 기존 39 B 기준선과 같은 세계의 짝비교로 묶지 않는다. 새 프로필에서는 기준 정책도 동일한 세계·seed·일정으로 수집한다. 결과를 읽기 전에 비교 계획과 원래 0.5 ms/연결 비열등 문턱을 고정한다. 실제 네트워크 측정·봉인·확증은 수행하지 않는다.

빌드 stage, Go의 -work 디렉터리, 시험 임시 파일, fresh 관문 입력은 보존한다. 이번 검증은 저장소 코드와 명시한 산출물의 범위이며 Go 내부 캐시 전체의 수명주기를 증명하지 않는다.
