# gen33 개발 측정 러너

[devbed.py](../experiments/v33/devbed.py)는 [final_bundle_v1.json](../g3/v33/plans/final_bundle_v1.json)의 팔·셀·블록을 실행 단위로 만든다. 결과 표지는 `development`, `confirmatory=false`이며 정책 판본은 `padfec3.learn3.POLICY_VERSION`에서 읽는다. F22~F25에서는 실제 QUIC 측정을 시작하지 않았다. 서버 자료의 세부 검사와 C1 분류는 [서버 수집과 C1 검사.md](서버%20수집과%20C1%20검사.md), 결과 생성은 [개발 측정 결과 생성.md](개발%20측정%20결과%20생성.md), Windows 실행과 복구는 [Windows 측정 실행기.md](Windows%20측정%20실행기.md)에 있다. 실제 smoke는 F26에서 확인한다.

## CLI와 선검사

저장소 루트에서 다음 명령은 파일을 만들거나 프로세스를 띄우지 않고 계획만 출력한다.

```powershell
wsl -d Ubuntu --exec python3 -I -B experiments/v33/devbed.py --plan g3/v33/plans/final_bundle_v1.json --dry-run
```

`--smoke`는 M0, `--run --task <ID>`는 지정한 과제 하나를 고른다. `--resume`과 `--report-only`에는 같은 `--run-id`와 `--task`를 준다. 잠금 경로와 SHA 산출물 폴더는 각각 `--lock`, `--artifacts-dir`로 받는다. 원자료는 로컬 보존 경로 `~/v33_runs/<run-id>/`에만 둔다. `--raw-dir`로 지정해도 이 위치와 같아야 한다. 실행 사본을 쓸 때는 `--binary gen33=<경로>`처럼 계획의 바이너리 ID별 경로를 전달한다.

live 모드는 바이너리 sha·srcsha의 null을 거부한다. 계획 JSON과 companion 문서는 각각 추적 상태, staged·unstaged 변경, 경로의 마지막 변경 커밋, 그 커밋의 blob과 실제 파일 바이트를 확인한다. JSON 재직렬화 해시를 쓰지 않는다. 각 단위의 실제 시작 시각은 두 계획 파일의 변경 커밋 시각보다 뒤여야 한다. 검사 실패는 종료 코드 2다.

`experiments.v33.devreport.report_run` 연결이 없으면 측정 폴더와 잠금을 만들기 전에 종료 코드 2를 반환한다. X1·X6·X9에는 `--m1-result`가 필요하다. M1 과제 식별, development 표지, 정상 실행 상태, 계획 SHA, 필수 대조와 블록 수, 봉인 기준값 대조를 확인하고 입력 JSON과 SHA를 저장한다. 구간이 넓어 판정불능인 것만으로 후속 실행을 막지는 않는다.

## 순서와 집계 구간

[arms.py](../experiments/v33/lib/arms.py)는 짝수 n에서 n행, 홀수 n에서 정방향·역방향을 합친 2n행의 일반 Williams 정사각을 만든다. 셀·궤적 안에서 phase를 넘어 센 블록 번호와 궤적 번호의 합으로 행을 고른다. 사용자가 과제 순서를 다르게 입력해도 계획 순서를 따른다.

M0는 번인이 없다. X6는 팔·셀·궤적별 첫 300연결을 번인으로 표시하고 phase 사이에는 캐시를 유지한다. X9는 매 블록의 첫 5연결을 워밍업으로 표시한다. 일정에는 원래 연결 수와 분석에 쓰는 연결 수를 함께 남긴다. optional 과제는 현재 실행을 거부하며 F31에서 선행 결과와 별도 계획 조건을 확인한 뒤 연결한다.

필수 팔에는 `-ips`를 넣지 않는다. 계획의 팔에 `ips` 키가 있을 때만 전달하며 실제 행의 `ips_eff`가 다르면 그 단위의 `checks.ips`는 fail이다. v33none과 v33c1은 다른 캐시를 쓰고, C1 클라이언트는 계획의 개별 플래그와 대기 시간을 따른다. X9 서버는 공통 `sealed31`과 `-udp-path basic`을 쓰며 클라이언트는 프로필 없이 tracer를 켠다.

1-RTT 분류는 p21의 strict 비교식을 쓴다. parity의 선행 바이트는 first flight parity 계수에서, padding의 선행 바이트는 `extra_sent`의 `first_bytes`, `first_sent`, `first_lead`에서 계산한다. 동결 행에 lead 계수가 없으면 p21의 정수 필드 fallback을 쓴다. 연결 종료 후 대기는 `0.3+2×RTT/1000`초다.

## 단위 실행과 저널

[transport.py](../experiments/v33/lib/transport.py)는 F21의 [netbed.py](../experiments/v33/lib/netbed.py)와 연결된다. main 스레드에서 CPU를 고정하고 자식 qamp를 띄운다. 매 단위 전 바이너리 SHA-256과 srcsha를 다시 읽고 gen33은 현재 quicbed 소스 지문도 대조한다. 동결 팔은 그 세대의 계획 지문을 쓴다.

gen33 서버의 인증서는 셀마다 생성해 팔들이 공유한다. PEM은 로컬 보존 경로 `~/v33_runs/<run-id>/certs/` 안에만 둔다. 서버는 팔·블록마다 새 프로세스와 conn-log를 쓰고 READY를 확인한 뒤 클라이언트를 실행한다. settle 뒤 SIGTERM을 보내고 종료 코드를 확인한다. tc의 양방향 설정과 실행 전후 `tc -s` 응답, 클라이언트·서버 stdout·stderr·stats를 남긴다. 행에는 계획·클라이언트 바이너리·서버 바이너리 지문을 붙인다.

[blocks.py](../experiments/v33/lib/blocks.py)의 저널 파일 이름에는 run ID가 들어간다. 새 실행은 기존 파일을 덮지 않는다. 한 블록의 모든 팔을 검증한 뒤 하나의 JSONL 레코드로 기록하고 fsync한다. 시작·netem·실패 event는 별도로 보존하며 완료 블록 수에 넣지 않는다. 파손 행, 지문 불일치, 중복, 순서 오류를 건너뛰지 않는다.

지문은 계획 파일 SHA, 바이너리별 SHA·srcsha, `experiments/v33/devbed.py`, `experiments/v33/devreport.py`, `experiments/padbed.py`, `experiments/gate_v3_parity.py`와 `experiments/v33/lib/*.py`의 실제 바이트로 만든다. 환경 정보와 다른 experiments 파일은 지문에 들어가지 않는다. 지문이 바뀐 뒤 완료 측정은 [devbed.py](../experiments/v33/devbed.py)의 report-only와 resume이 거부하므로 [devreport.py](../experiments/v33/devreport.py)의 report-only로 재생성한다. 이 경로는 manifest에 저장된 지문을 쓴다. 측정별 러너 코드는 M0 `fe00e6ede`, M1 `38e5592ce`, X1·X9·X6 `098410ad8`의 트리로 지문이 재현되고, `experiments/padbed.py`, `experiments/gate_v3_parity.py`는 이 기간에 바뀌지 않았다. `experiments/v33/devreport.py`는 M0 `8897a733`, M1·X1·X9 `fa68876a`, X6 `2508e463`(blob sha256 앞 8자리)이다. 환경의 `uname_r`, `python3_V`, `tc_V`, `ip_V`, `cpu_list`, `cpu_count`와 Python 실행 정보는 최초 metadata에 저장한다.

재개는 마지막 연속 완료 블록의 캐시 bytes를 새 attempt 폴더에 복원한다. 불완전 블록의 팔은 모두 다시 실행하며 앞선 attempt의 캐시와 원자료는 보존한다. 캐시 snapshot은 크기와 SHA를 검증하고, 세대별 JSON 구조·schema·목적지를 확인한다. 이 검사는 정책 loader 전체의 의미 검증을 복제하지 않는다. 재개 전에는 원자료 로그 SHA도 대조한다.

## 잠금과 보고서 연결

러너가 첫 단위 전에 잠금을 만들고 5초 주기의 별도 스레드로 heartbeat를 기록한다. 상태에는 재개 명령도 남긴다. 잠금 키는 `task`, `started_kst`, `expected_end_kst`, `wsl_pid`, `status_file`, `done_marker`다. task는 F26 같은 카드 ID이고 상태의 `measurement_task`는 M0 같은 측정 ID다. 스레드 오류나 잠금 소유권 변경은 실패로 처리한다.

모든 단위를 기록하면 DONE을 만든다. report 실패나 SHA 검증 실패에는 잠금을 남긴다. `report-only`는 완료 저널을 읽고 네트워크 실행 없이 다시 보고한다. report 전후 저널·manifest·원자료·M1 입력의 바이트가 같아야 하며, SHA 목록에는 결과·저널·완료 단위의 모든 원자료 로그가 들어 있어야 한다. 이 검사가 통과한 뒤에만 잠금을 지운다.

결과 생성기의 함수 계약은 다음과 같다.

```python
report_run(journal_path, *, plan_path, raw_dir, artifacts_dir, m1_result=None)
```

반환 객체에는 `result_path`, `document_path`, `artifacts_manifest`가 있다. SHA 목록은 sha256sum 형식이며 상대 경로는 그 목록 파일의 부모를 기준으로 읽는다. 생성기는 로컬 보존 원자료의 `manifest_<run-id>.json`에 든 계획과 최초 metadata, 저널을 입력으로 삼는다. 원자료를 수정하거나 report-only 시각·새 환경을 결과에 넣지 않는다. 동일 바이트 재현은 F24에서 fixture로 검사하며 실제 smoke의 재현은 F26에서 확인한다.

[report.py](../experiments/v33/lib/report.py)는 실행/자료 상태를 자료 없음·판정 실패·판정 통과로 구분한다. M1 C/D 구간이 계획 허용 오차 밖이면 별도 `inference_status`와 결과의 통계 `status`를 판정불능으로 둔다. bigcert 2%에만 적용하는 A/A 자와 유효 RTT 비율의 경고 helper도 제공한다. 셀·팔 관측 집계는 `observations.summarize_observations`를 통해 결과 문서로 이어진다. 실제 idle은 절대시각 부재로 미확인이다.

## 검증 범위

Windows 시험은 일반 Williams 순서, 계획 선커밋, 무쓰기 dry-run, 지문 범위, 캐시 복원, 중단·재개, heartbeat, 프로세스 실패와 report 복구를 검사한다. 프로세스 시험은 fixture다. 실제 동결 qamp의 클라이언트 플래그는 n=0으로 확인했고 인증서 생성기는 dry-run metadata만 확인했다. QUIC 성능과 실제 C1 수신률, conn-log 완전성은 미확인이다.

실행·집계 스크립트와 로그는 로컬 보존 폴더 `C:/dev/codex_handoff/final/runs/`의 `F22_verify.py`, `F22_wsl_check.py`, `F22_summary.json`, `F22_accept.txt`에 둔다. 최초 PID 검사와 CLI 검증용 캐시 공유 오류는 실패 기록에 남겼다. Go·정책·계획 파일과 설치·동결 바이너리는 변경하지 않았다.
