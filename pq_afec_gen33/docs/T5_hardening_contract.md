# T5 수신 경계와 자원 수명

클라이언트는 첫 Initial을 소켓에 쓰기 전에 peer와 자신의 SCID를 저장한다. 직접 생성하는 CID도 최대 64개 등록하므로 정상 CID 회전을 따라간다. 같은 peer이고 이 연결이 발급한 CID로 향하는 QUIC v1 롱헤더 또는 짧은 헤더만 서버 바이트·srvBig·C1 관측에 넣는다. 거부한 datagram은 별도 계수로 남긴다. 주소와 CID 일치는 인증 증거가 아니다. 연결 이전이나 다른 CID의 자료를 현재 연결에 섞지 않는 검사다.

연결 계정의 상한 4096과 alias 상한 16을 유지한다. 새 계정이 필요하면 최근 사용 시각이 가장 오래된 계정을 축출한다. 실제 Listener.Accept가 반환한 연결의 context와 원래 DCID를 연결해 handshake 완료 시각을 기록하고 10초 뒤 계정과 CID 색인을 지운다. 완료 전에 닫힌 연결도 종료 시각부터 10초 보관한다. 평문 Handshake 헤더를 완료 통지로 사용하지 않는다. 진행 중 계정을 상한 때문에 축출한 경우에는 ConnAcctDropped도 올려 자료 누락을 경고한다. 서로 충돌했던 CID는 마지막 소유 계정이 없어질 때까지 모호한 상태를 유지한다.

클라이언트의 첫 서버 응답 전 Initial이 아닌 롱헤더 송신을 계수하고 거부한다. 서버 수신에서도 첫 송신 전 같은 위반을 진단한다. 이 검사는 실험 송신기의 형태를 제한하며 quic-go 자체의 미복호 Handshake 재처리 결함을 고치는 것은 아니다. 배포용 인증과 서버 공격 방어의 한계는 c1_threat_model.md에 따로 기록한다.

복호기 DCID 색인과 UDP OOB 경로는 별도 변경으로 검증한다. 고정 quic-go v0.61.0의 sys_conn_oob.go는 ReadBatch가 없으면 SyscallConn으로 읽기를 우회한다. 래퍼는 ReadBatch도 복호기에 연결해야 한다. 복원 datagram에 존재하지 않는 물리 ECN 정보를 만들어 붙이지 않으며, GSO 송신 바이트와 datagram 계수는 실제 segment 단위로 대조해야 한다.

검증은 잘못된 peer·CID·짧은 헤더, 수신과 첫 송신의 경합,5000계정의 수명·LRU·alias 정리, 기존 ReadFrom 전수와 실제 QUIC C1 기능을 포함한다. 기능 검증의 실행 시간을 HCT 성능으로 해석하지 않는다. X3의 같은 블록 비교가 끝나기 전에는 UDP 경로가 경주 확률을 개선했다고 쓰지 않는다.
