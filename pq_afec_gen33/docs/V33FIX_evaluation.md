## 1. 무엇을 했나

1. 작업 트리 정책을 스크래치에 복사해 고정했다(`policy_snapshot`, 영수증 SHA-256 `bd76142a48e01617ba49f3eb31875fb9b1d18b5f095cbabdaf84d18806cd10b8`). 복사 전에 작업 트리의 `afec`, `padfec`, `padfec3` 19개 파일 지문이 A-py 재생 기록(`g3/v33/V33FIX_replay_v1.json`의 `policy_sources_sha256`)과 같은지 확인했다. 다른 묶음이 같은 작업 트리를 고치는 중이라, 실행 중 바뀌지 않게 하려고 사본으로 돌렸다.
2. 이 사본을 L3 수집기와 같은 연결 루프(`bench_learning_l3.run_seed`, 정책 worker는 `policy_worker.py`)로 W1 15셀에 폐루프로 돌렸다. 과제는 seed 31~34 확인과 불일치 셀의 20 seed였는데, 실행 하나가 약 3초라 none·c1 두 모드의 15셀 × seed 31~50 전부(600실행, 822,000연결)를 돌렸다 [J]. seed 31~34(120실행)를 먼저 돌려 대조했고 그다음 35~50을 더했다.
3. 새 궤적을 연결마다 원자료와 대조했다. none은 `W1_raw_v32`, c1은 L3 record_only c1 원자료(`L3_raw_v1_*` 가운데 overlay가 `L3_record_only_v1.json`인 15개)다 [T].
4. 기존 보고 규칙을 그대로 써서 기대 비용 비교를 계산했다. 집계는 `bench_report.aggregate`와 `bench_report.direct_comparison`, B3·B4 p 수렴은 `bench_learning_report.convergence`, 문턱은 `g3/v33/bench_protocol.json`과 `g3/v33/bench_reporting_rules.json`(SHA-256이 `L3_benchmark_v1.json` 기록과 같음을 확인)이다. seed 구간은 95% Student t, MC는 행동 작업 묶음별 99% 정규근사이고 seed 수의 제곱근으로 나누지 않는다.
5. 행동 비용표 두 개로 같은 계산을 각각 했다. (i) N=131072 L3 joint action pool(`runs\L3_joint_action_pool_v1`, family 101, seed 850001), (ii) N=1048576 L1 정밀 표(`runs\L1_action_pool_precision_v2`, family 100). 새 실행이 고른 (문맥, 행동)은 두 표에 모두 있었다(누락 0, 두 집계 모두 `missing` 빈 목록) [J]. 두 표의 결과 파일 해시를 `L3_benchmark_v1.json`과 `L1_benchmark_precision_v1.json`의 pool 증명 목록과 대조했고, 결과마다 `bench_oracles.validate_oracle_result`로 다시 검증했다. 비교용 과거 원자료(v31, v32, L1 none·c1, record c1)는 요약과 궤적 파일 해시를 L3 joint family plan(`runs\L3_joint_action_family_v1.json`, SHA-256 `3e31108f…262ad`)의 입력 목록과 대조했다.
6. 채택 바닥 조건에서 미확정이 나온 B6을 새 seed로 한 번 독립 반복했다. 계획 파일을 먼저 쓰고(2026-11-02 02:46:55, SHA-256 `c6d7c7e28752fa2bd573a5fedd68c52044841e930bd78b71559efa06cb5a8402`) 그 뒤에 첫 실행을 시작했다(02:48:45) [P].

궤적이 다른 실행은 c1 B11 seed 42와 50이다 [T]. 첫 c1 회신을 각각 236번째, 205번째 연결에서 받았고(c1 표지가 처음 켜진 결정 인덱스 237, 206), 그 전까지 설계 규칙 2대로 v3.2 이진 우도로 배웠다. 결정 전 p_mean은 인덱스 2부터 다르고, 행동은 인덱스 187에서 처음 다르며 실행마다 10연결에서 다르다. 그래서 이 재판정은 A-py의 재생 추론(새 정책 none = v32, c1 = record_c1)에 기대지 않고, 폐루프 600실행 자체를 새 정책의 원자료로 쓴다.

## 3. 판정 규칙

- 채택 바닥 조건(TASKS.md L 공통 1, 과제 지시): v331_none과 v331_c1이 각각 v32 대비 15셀 모두 0.5 ms/연결 비열등이어야 한다. 셀마다 seed 95% 상한에 공유 MC 폭을 더한 조정 상한이 0.5 이하이면 pass, 조정 하한이 0.5를 넘으면 fail, 그 밖은 미확정이다. 한 셀의 개선으로 다른 셀을 상쇄하지 않는다. 미확정은 통과가 아니다.
- 두 표를 모든 비교에 똑같이 적용하고 나란히 적는다. 정밀 표는 L1 때와 같은 조건(seed 850001의 앞부분을 다시 포함하는 사후 개발 정밀화)이다.
- 함께 적는 비교: v31 대비(W1 프로토콜 원래 문턱), L1 대비(당시 활성 정책 대비 악화 없음), c1 대 none, c1 대 record_c1(진단).
- 절대 목표는 프로토콜 문턱 그대로다. B1 후회 < 0.1, B2 후회 < 0.5 ms/연결(seed 상한 + MC + 선택 오차), B1 높은 손실 구간 |p 편향| < 0.005, B4 서버 추가 바이트 < 1855 B, B5 교체 적응 ≤ 2연결. L1 카드의 B3·B4 결정 전 p_mean < 0.01 수렴도 적는다.
- 셀 사이 다중 비교 보정은 하지 않았다. 기존 규칙에 없기 때문이다. 셀별 "증가", "감소" 표시는 보정 없는 표시다(감사 C-E8).
