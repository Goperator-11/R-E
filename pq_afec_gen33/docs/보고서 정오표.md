# 보고서 정오표 2판

F32에서 X1, X9, X6 개발 측정 결과를 넣은 정오표 2판이다. 1판은 F04에서 원자료 수치와 적용 조건을 확인하였다. BL-09는 F42의 후보 평가 기록 14개와 활성에 남은 경로를 반영했다. 후보 수 확정과 네트워크 측정 대기는 별도다. RT-08은 실행 기록 확인 전까지 값은 유지하고 캡션의 단정만 고치는 기본안이다. 표 칸의 실제 줄 수와 PDF 문구·쪽수는 사람 확인으로 남긴다.

이 표는 보고서에 옮길 수정안이다. 로컬 보존 원본 `content.py`, 제출 HWP와 `report_repro/content.py` 사본에는 적용하지 않았다. `content.py 줄`은 원본 기준이며 사본은 인코딩 선언 한 줄이 빠져 있다. old와 new는 백틱 안의 JSON 문자열이다. 이어 쓴 Python 문자열은 AST에서 합친 값으로 대조한다.

분량 증감은 문자열 안의 명시적 줄바꿈 증감이다. 같은 문단이나 표 칸의 교체는 0이며, 한글의 자동 줄바꿈과 인쇄 쪽수는 미확인이다. 요약문 2쪽, 과정 2쪽, 결과물 12쪽의 실제 분량은 최종 PDF에서 사람이 확인해야 한다.

D57의 기본값은 현행 AI 활용 문구 유지다. RT-01의 new는 결정 뒤에만 적용할 후보이며 현재는 결정 대기다. 적용 여부는 `적용` 열에 적는다. RT-23의 new만 측정 대기 문장으로 남아 있으며 F31을 돌리지 않으면 적용하지 않는다. 개발 측정은 봉인 판정에 합치지 않는다. RT-05는 F05 재계산에서 저장한 숫자로 갱신하였으며, RT-21은 실제 검색 기록이 생긴 뒤 날짜와 범위를 확정한다.

## 측정 상태별 선택

RT-04의 selected 17개는 F32에서 `측정 뒤 문구`로 정했고, new와 측정 뒤 문구 열에 같은 최종 문구를 넣었다. 측정 뒤 문구는 근거 과제의 결과가 실제로 생성되고 검증된 경우에만 고른다. 차이가 검출되지 않거나 판정불능이어도 측정한 결과이며, 측정 못 한 경우로 바꾸지 않는다. 결과 수치는 F32에서 해당 결과 파일의 키와 연결해 채우고 RT-03의 결과 문단과 함께 대조한다. X9는 해당 조건의 PTO 비교이며 손실 취약성의 일반 가설을 확정하거나 기각하지 않는다. X6로 v3.2-dev 자체를 측정했다고 쓰지 않는다.

52행의 old는 문단 전체다. 앞의 `(미해결)`과 과거 미실행 문장이 측정 뒤에도 남지 않도록 교체 범위를 넓혔다. T7의 추적 범위는 F22~F26이며, 문구 선택은 F32·F33 카드의 구체적인 조정에 따른다. F22가 skipped이면 원문 유지, F22가 done이고 F28~F30이 모두 skipped이면 러너 구현 뒤 미측정 문구, 하나라도 측정했으면 아래의 실제 완료 조합을 고른다. 아직 진행 중이거나 결과 검증이 진행 중인 상태에서는 selected를 확정하지 않는다. 실패가 확정된 failed 상태는 측정 못 한 경우 문구와 혼합표의 not_measured 분기를 고르되, final_measure_status에는 실제 failed 상태와 실패 사유를 보존한다.
