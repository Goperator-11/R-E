# T4 관측 계약

이 문서는 기능 시험 전에 고정한 개발 계약이다. 활성 정책은 L1 상태4, lead-hold는 기본 off다. 정책의 비용식이나 세계 시뮬레이터를 바꾸지 않는다.

C1 판본3은 실제 수신 CRC와 복원 CRC를 별도 목록으로 보낸다. 두 목록의 상한은 각각64개이며 초과 여부를 남긴다. 판본2는 읽되 복원 목록이 없는 자료로 표시한다. 첫 비행 도착 비트는 원본 순서 다음 패리티 송신 순서다. 이 순서는 시간순 비트맵이 아니므로 버스트 추정에 그대로 쓰면 안 된다. 검증용 소거는 계획한 송신 목록에 포함하며, 소켓 쓰기 실패나 중복 송신 CRC가 있으면 관측을 검열한다. CRC가 겹치거나 목록이 잘리면 손실 관측을 학습에 쓰지 않는다. CRC는 인증 수단이 아니다.

원래 수신 Handshake와 복원되어 스택에 넘기는 Handshake에서 같은 회신 함수를 호출한다. 회신은 연결당 한 번이다. 이 계층은 Handshake 헤더를 식별할 뿐 AEAD 검증 완료를 확인하지 못한다. 기존 평문 부채널의 인증·주소검증 한계는 T5의 위협 모형에서 다룬다. 첫 비행 중 회신하는 개발 플래그 fbEarly는 정상 관측에 쓰지 않는다.

arrivals는 L1의 src/sent/lost/bitmap/trunc 형식이다. C1이 없으면 src=none, sent=lost=0, bitmap=null이다. PTO나 연결 실패를 전멸 증거로 쓰지 않는다(D13). 유효한 C1은 auto3의 기존 관측 함수에 전달하고 gen-2도 같은 확인된 도착 수를 쓴다. C1을 끄면 기존 none 경로를 유지한다. 이 연결의 관측은 다음 결정에만 반영된다.

클라이언트의 메모리 qlog 기록기는 Initial ACK range, 수신·송신 패킷 번호와 CRYPTO 구간, PTO 타이머 만료, LatestRTT 변경 표본을 저장한다. 시각은 Dial 시작 기준 단조 시계 ns다. RTT 자료는 quic-go가 실제 표본을 얻은 뒤 내보낸 변경 이벤트이며, 같은 RTT 값이 반복되면 모든 ACK 표본이 별도로 나오지는 않는다. ACK는 복원된 패킷도 확인하므로 물리 도착 우도로 변환하지 않는다. 각 목록과 프레임 수에는 상한을 두고 잘림을 표시한다.

fecConn.ReadFrom은 서버 데이터그램의 수신 시각·크기·CRC32c·C1 여부·첫 큰 응답 이전 여부를 기록한다. qlog의 패킷 길이와 UDP 길이는 다르며 코얼레스된 패킷을 합쳐 중복 계산하지 않는다. CRC32c가0이면 qlog 연결 키가 없는 것으로 취급한다. 완료 뒤 수신도 포함되므로 Dial 완료 시각을 별도로 남긴다. 이 목록을 서버 송신 총량이나 손실 없는 첫 비행 크기라고 부르지 않는다.

unrecoverable_seen은 기존의 중간 복구 불가 관측 수를 유지한다. unrecoverable_final은 알려진 FEC 비행이 수신기 TTL에 도달했을 때 원본도 복원본도 없는 경우를 한 번 센다. flights_finalized와 아직 열린 비행 수를 함께 기록한다. 모든 패리티를 잃어 비행 기록 자체가 없는 경우는 분모에 없다. TTL 뒤 늦은 원본이 오는 무제한 시간의 최종 손실을 뜻하지 않는다. hold 수신기도 같은 종료 시점의 의미로 센다.

검증은 와이어 왕복·이전 판본·잘림·중복·재전송·복원 Handshake·TTL 종료, 메모리 스냅숏 독립성, 실제 QUIC의 지연·소거 기능 시험을 포함한다. RTT200의 과거 표본 부재는 새 관측으로 진단하며 과거 자료를 덮어쓰지 않는다. 시간 출력은 기능 진단이며 성능 개선 근거가 아니다.

구현 검토에서 추가한 한계: 고정 quic-go의 OnLossDetectionTimeout은 bytesInFlight=0이고 주소검증이 끝나지 않은 분기에서 qlog 이벤트 없이 ptoCount를 늘린다. 따라서 pto_count_scope는 qlog_loss_timer_expired_lower_bound다. 기록된 타이머 만료 수를 모든 내부 PTO의 정확한 수라고 쓰지 않는다. 외부 설정이나 정책을 바꿔 이 한계를 감추지 않는다. T6·T7에서 같은 범위를 유지해야 한다.

수신 목록과 server_bytes는 같은 메모리 스냅숏에서 읽는다. 다른 시점에 읽은 countConn 합계와 섞지 않는다. 목록 상한에 걸려도 누적 바이트는 계속 세며 truncated=true를 남긴다. 경과 시각과 실제 전송 순서는 기능 진단에만 쓰고, 계측 비용의 성능 영향은 T7의 A/A 검증 범위다.

T4_smoke_v2에서 RTT200 회신 한 건이 기존200ms 대기 한도를 넘었다. 서버는3개 연결 모두 회신했고 세 번째 클라이언트는 HCT219.213ms 뒤 약202.6ms까지 수집했으나 회신을 받지 못했다. D23에 따라 feedback-wait를 별도 CLI 설정으로 추가하고 기본1초로 둔다. HCT는 그대로 대기 전에 측정하며 실제 대기 시간과 수신 여부를 행에 기록한다. 원래 실패 자료와 검사 조건을 보존한다. 새 설정의 연결 간격 영향은 T7 비교 조건에 포함한다.
