# M1 개발 평가 계획

M1의 정책 후보와 수신기 변경을 분리해 평가한다. 이 계획은 성능 결과를 열람하기 전에 작성한다. 활성 정책은 L1 상태 4이고, 별도 M1 후보는 상태 10이다. 후보는 보류 복호의 사건 비용과 그 사건에서 계산한 세 등급 확률을 사용한다. L1의 등급 경계, 사전, 감시, 재평가 주기와 후보 행동 집합은 그대로 둔다. 이전 상태는 거부한다.

수신기 세계는 두 가지다. `off`는 기존 신용 전용 선행 경로이고 `hold`는 D20의 첫 패리티 수신 시각, 남은 명목 슬롯, margin 1 ms를 사용한다. 업링크 속도는 각 문맥에 명시된 Mbps를 정수 kbps로 변환한 입력이다. 자동 추정값이 아니다. TTL 1초, 최근 원본 수명 3초, 비행 payload 한도 32768 B를 고정한다. 직렬화와 손실 위치를 비롯한 나머지 세계 매개변수는 W0에서 가져온다. 기존 W0와 W1 파일은 수정하지 않는다.

별도 `worldsim_m1.py`는 정책과 Python 기준 복호기를 import하지 않는다. 독립 `world_receiver_m1.py`에서 실제 수신 사건을 처리한다. 표준 순서의 k≤4, m≤4, 유효 metadata·CRC, 단일 연결과 전체 비행 재전송이 평가 범위다. 실제 UDP 큐, OS 지터, 다중 연결의 전체 메모리 압력과 RSS를 재현하지 않는다. 이 범위 밖의 오류·중복·cap·Close는 Go 시험과 사건 기준의 별도 검증으로 남긴다. 세계의 이 제한을 일반 서버에 대한 보장으로 쓰지 않는다.

L1·M1 두 정책을 off·hold 두 세계에서 각각 실행한다. 네 조합 모두 W1의 15셀, seed 31~50, 전체 연결 수와 손실 일정을 사용한다. none·c1·ideal을 모두 수집한다. ideal은 진단이며 C1을 대신하지 않는다. 관측기는 L1의 수동 C1 계약 그대로다. 각 세계의 B0와 (0,3,1) 고정 행동을 다시 생성하고, 서로 다른 세계의 자료를 같은 세계 비교로 표시하지 않는다.

주 비교는 다음 세 종류다. none·c1의 각 15셀에서 모두 판정한다.

- hold 세계 안의 M1에서 L1을 뺀 차이, 비용·우도 연결의 기여다.
- M1/hold에서 L1/off를 뺀 차이, 정책과 수신기를 함께 바꾼 끝점 비교다.
- M1/hold에서 과거 v31/off 및 v32/off를 뺀 차이, W1의 이전 세대 대조다. 과거 자료는 원래 해시와 seed·문맥·행동 이력을 검증해 사용한다.

기대 비용을 주 결과로 쓴다. seed 단위 95% 구간과 전체 행동 가족의 공통 MC 오차를 합친 상한이 0.5 ms/연결 이하여야 비열등을 통과한다. C1 끝점 비교에서 보정 상한이 0 미만인 셀이 하나 이상 있어야 개선 조건을 통과한다. 주 비교 하나라도 실패하거나 미확정이면 채택하지 않는다. 실현 HCT, 바이트, 손실 추정 편향과 행동 선택은 진단으로 함께 보고한다. off 세계의 M1은 서버 기능이 없는 경우의 부적합 진단이며 채택의 주 비교로 쓰지 않는다.

MC는 모든 수집이 끝난 뒤 관측된 행동의 합집합을 고정해 수행한다. 표본 수 131072, seed 850001과 기존 W1의 공통 난수·가족 오차 산식을 쓴다. 두 세계를 비교할 때는 같은 환경 난수의 행동·세계별 기대 비용을 각각 계산하고 결합한 오차를 쓴다. 성능에 따라 행동을 빼거나 표본 수를 늘리지 않는다. 서로 다른 행동의 수치상 영분산 때문에 경계를 정의할 수 없으면 미확정으로 남긴다. 절대 최적 후회는 별도 최적 참조 검증 없이 주장하지 않는다.

과제 카드의 고정 행동 검사는 별도로 보고한다. 큰 인증서 문맥 k=2, W=1280 B, RTT=50 ms, 업링크=2 Mbps, cert=16000 B에서 p=0.02와 0.15를 사용한다. 모든 m≤4의 lead·trailing 배분과 기존 후보의 delta를 빠짐없이 평가한다. (0,3,1)의 첫 비행 실패 확률 약 0.0004는 유효 심볼·수명 범위의 소거 집합 전수와 독립 세계의 동일 집합으로 확인한다. 최선 J3 개선 약 10 ms는 모델 값으로 표를 만들고, 독립 세계의 기대 HCT 변화는 별도 열에 둔다. '약 10 ms'를 결과를 보고 정한 합격 구간으로 바꾸지 않는다. 2%에서 보류로 생긴 손해와 각 행동의 명목 deadline 비용을 함께 표로 내고 비교한다. 감사자의 과거 숫자를 새 실행값으로 쓰지 않는다.

수집 전에 소스·사본·계획을 해시로 고정하고 커밋한다. dry-run과 smoke에서는 입력 경계, 전체 목록, seed 인덱스, 저장·재생을 검사한다. smoke 성능값으로 계획을 바꾸지 않는다. 전체 수집 뒤 원자료와 행동 빈도, 관측 이력, 세계·정책 지문을 독립 검사한다. 실제 quic-go 연결 큐의 첫 송신 신용과 Go 정책의 비트 일치 관문은 Python 성능 결과로 대체하지 않는다. 이 계획은 개발 시뮬레이션이며 물리 측정이나 확증 계획이 아니다.
