# 미채택 후보 14개의 개발 평가 기록

이 문서는 L2, L3, L5, J1, J6, J7, M1, O2, J5, O3, O4, J3, M4, J8의 개발 시뮬레이션 평가 기록을 모은다. 모형 계산, 독립 사건 세계, 기존 전송 trace의 진단·재생을 문단마다 구분한다. 새 성능 측정이나 confirmatory 판정은 없으며, 미확정은 차이가 없다는 뜻도 성능 악화가 확인됐다는 뜻도 아니다. 후보 전체를 활성 정책에 넣은 경우는 없다. 현재 v3.3.1-dev에 남은 것은 `c1_seen=True` 경로의 L1 관측과 L3 `record_only` 결정, J7에서 분리한 parity datagram의 1452 B 상한이다. C1은 표준 QUIC에 없는 서버 회신이고, 이 개발 세계의 C1 회신 비용은 0 가정이다. `c1_seen=False` 경로는 parity 상한을 맞춘 v3.2-dev와 관측·결정을 같이하며, 원래 v3.2-dev와의 재생 동치는 W1 입력 범위에서 확인했다. 정책과 동치 범위는 [활성 정책 명세](v3.3.1%20활성%20정책%20수정.md)를 따른다.

판정 기준 D47은 none·c1을 포함한 모든 배포 경로가 v3.2-dev 대비 W1의 모든 셀에서 조정 상한 0.5 ms/연결 이하일 것을 요구한다. 과거 후보의 원래 L1 대비 판정과 D47을 구분하며, 끝난 평가를 새 규칙으로 소급해 채택하지 않는다. [판정 규칙](v3.3.1%20판정%20규칙.md)의 Z1은 서로 다른 행동의 관측 분산이 0에 가까워 MC 경계가 null인 경우 독립 seed로 비짝 평가해 MC 경계를 채운다. 실제 적용을 마친 곳은 J6 c6000 두 셀이며, 다른 null 경계는 미확정으로 남는다. seed 구간과 MC 경계를 합친 조정 구간을 전체 동시 신뢰수준의 보장으로 해석하지 않는다. 후보 상태는 미채택 또는 보류로 기록하고, 보류했던 재진입 과제는 이번 최종 루프에서 다시 실행하지 않는다.

각 차이는 별도 표시가 없으면 후보에서 비교 기준을 뺀 ms/연결이다. 음수는 후보 비용이 작다는 뜻이다. 원자료 JSON의 지정 키와 표시 자리수는 로컬 보존 `C:/dev/codex_handoff/final/runs/F42_learning_evidence.json`, `C:/dev/codex_handoff/final/runs/F42_model_evidence.json`, `C:/dev/codex_handoff/final/runs/F42_runtime_evidence.json`에 연결했고, 같은 폴더의 `F42_verify.py`가 읽기 전용으로 대조한다. 아래 validation 경로는 로컬 보존 자료다. 배포본에는 validation 묶음이 포함되지 않으므로 기존 결과 문서와 원자료 위치를 함께 남긴다.

## L2

개발 시뮬레이션에서 목적지별 EPS를 Beta(1,999)로 학습하는 후보를 평가했다. none B8_j10의 L1 대비 차이는 -1.568806 ms, 조정 구간은 [-4.859306, 1.721694] ms로 비열등이 미확정이었다. 평균 감소는 seed 46의 -31.376 ms에서 나왔고 나머지 seed의 차이는 0이었다. 이 단일 seed의 쌍안정 결과를 EPS 학습의 일반적인 개선으로 쓰지 않는다. EPS 적응은 미채택이며, 3등급 라벨은 L1 관측에 남아 c1 경로에서 쓰인다. 원자료는 `g3/v33/L2_benchmark_v1.json`의 `comparisons[113]`이며, 원래 판정은 [L2 기록](L2%20후보%20보류.md), seed 46 해석은 [판정 규칙 2.4·2.5절](v3.3.1%20판정%20규칙.md)에 있다.

## L3

개발 시뮬레이션에서 CUSUM 감시와 β 반응을 넣었다. 전체 후보의 c1 B8_j20은 L1 대비 +0.867859 ms, 조정 구간 [0.569639, 1.166079] ms로 비열등에 실패했다. B1의 절대 기대 후회 보고값은 동결 선택 기준과의 격차이며 참 최적값과의 후회를 증명한 값은 아니다. 그 값은 0.093952 ms, 조정 구간 [0.060876, 0.127028] ms로 0.1 ms 목표가 미확정이었다. CUSUM·β 반응 후보는 미채택이며, 별도 진단 팔의 `record_only` 결정만 현재 c1 경로에 남았다. 이 팔도 B1 후회의 상한이 0.127028 ms라 목표 달성으로 쓰지 않는다. 현재 c1 경로에는 CUSUM 경보가 없다. 원자료는 `g3/v33/L3_benchmark_v1.json`의 대조와 `groups[120]`의 `record_c1` B1이며, [L3 원래 판정](L3%20판정.md)과 [활성 판의 별도 평가](v3.3.1%20W1%20재판정.md)를 구분한다.

## J6

## M1

개발 시뮬레이션에서 원본보다 먼저 온 parity를 보관했다가 복호하는 hold 후보를 평가했다. 주 비교 120셀은 통과 82, 실패 15, 미확정 23이었다. 대표 실패인 none B2의 hold/m1 대 hold/l1 차이는 +9.369509 ms였으며 조정 구간은 [8.041835, 10.697182] ms였다. hold 세계에만 parity 수신 뒤 서버 송신을 재개하는 결함이 있었다. 수신 계약상 복구할 수 없는 flight의 보관 parity는 TTL로 폐기되면 stack에 전달되지 않아 credit으로 계상되지 않는다. 이미 계상한 QUIC credit이 TTL 뒤 만료된다는 뜻은 아니다. 여기에 후보 비용 모형이 trailing=0인 (0,4,0)의 둘째 왕복 응답 손실 비용을 빠뜨린 결함이 겹쳤다(E-M1-1). 세계 결함만 고치면 채택된다는 결론을 내릴 수 없어 미채택으로 남겼으며, hold 정책은 활성에 들어가지 않았다. 보존된 Go 기능의 `lead-hold` 기본값도 off다. 원자료는 로컬 보존 `C:/dev/codex_handoff/v33/runs/M1_disposition_v2.json`의 `performance_decision`과 `g3/v33/M1_benchmark_v1.json`이며, 후보 비용 결함은 `g3/v33/V33FIX_world_diag_v1.json`의 `sections.m1_cost_model.b2_pure_lead`에 있다. [세계 정정 기록](v3.3.1%20세계%20시뮬레이터와%20판정%20통계.md)을 함께 읽는다. 이 후보 M1은 최종 측정 카드 F27의 M1 서버 등가·A/A 개발 측정과 별개다.

## O2

개발 시뮬레이션에서 uplink u를 모를 때 minimax로 행동을 고르는 참조를 평가했다. 모형의 최대 후회는 6.503042445 ms로 사전 기준 6.5 ms를 넘었고, 독립 세계의 240대조 중 16개는 보정 구간 하한이 6.5 ms를 넘었다. 예를 들어 B1·u0·p0.15의 고정 trailing4 대비 차이는 +10.543249 [8.728693, 12.357805] ms였다. 이는 지정 비교 행동에 대한 손해로부터 얻은 세계 최적 대비 후회의 하한이며, 나머지 대조를 상한 통과로 세지 않는다. 입력을 알고 있는 모형에서의 결과와 실제 추정기를 붙인 정책을 구분해 minimax 후보를 미채택으로 남겼다. 활성 정책은 설정한 uplink 입력을 쓰며 이 후보의 추정기를 채택하지 않았다. 원자료 위치와 구간은 [모형 참조 결과](O2%20참조와%20추정기%20진단%20결과.md)와 [세계 진단](O2%20세계%20진단%20결과.md)에 있고, JSON은 로컬 보존 `g3/v33/validation/O2_reference_v1/runs/O2_reference_report_v1/result.json`의 `models[1].nominal_choice.worst_regret_ms`와 `g3/v33/validation/O2_world_v1/runs/O2_world_full_v1/summary.json`의 `comparisons`·`counterexamples`다.

## J5

개발 시뮬레이션에서 Gilbert-Elliott(GE) burst 비용을 반영했다. B10에서 iid·known_burst·forced_burst3가 같은 행동을 골라 HCT 차이와 구간은 구조적으로 0, [0, 0] ms였다. 세계 평균 64.562675 ms와 모형 58.464599 ms 사이에는 6.098075 ms 잔차가 남았다. 알려진 p의 이 비교에서 감소 조건을 만족하지 못했고, p·burst 길이의 공동 학습과 후속 실패 상태 이월 비용도 미검증이므로 GE 후보는 미채택이다. GE가 다른 학습기에서도 이득을 줄 수 없다는 결론은 내리지 않는다. 활성 정책에는 GE 학습이나 비용식이 들어가지 않았다. 원자료는 로컬 보존 `g3/v33/validation/J5_world_v1/runs/J5_world_disposition_v1.json`의 `b10_world_mean_hct_ms`·`b10_model_hct_ms`·`b10_residual_ms`와 같은 runs 아래 `J5_world_full_v1/summary.json`의 `comparisons[15]`·`comparisons[16]`이며, [세계 진단 결과](J5%20세계%20진단과%20보류%20판정.md)에 모형·세계·역사 trace를 구분했다.

## O4

개발 시뮬레이션 평가의 일부로 현재 ClientHello에서 k를 계산하는 후보를 동결 W1 기록에 재생했다. 900실행·1,233,000연결에서 결정이 모두 같아 같은 세계의 HCT·바이트 차이는 구조적으로 0이고 HCT 구간도 [0, 0] ms였다. 이는 새 세계 실행이나 전송 측정 결과가 아니며, 기존 세계에서 현재 k와 과거 최빈값이 같았다는 재생 결과다. 후보별 k가 바뀌는 경우와 실제 송신 전 훅이 연결되지 않아 미채택으로 남겼다. 현재 ClientHello 기반 후보 정책은 활성에 넣지 않았으며, 별도 구현 기능 검증을 이 후보의 채택으로 세지 않는다. 원자료 위치는 [현재 k 재생 결과](O4%20현재%20k%20후보%20검증%20결과.md)와 로컬 보존 `g3/v33/validation/O4_current_v1/runs/O4_current_verify_v1.json`의 `runs`·`connections`·`decision_mismatches`·`groups`에 있다.

## J3

개발 시뮬레이션에서 실패 가지를 두 단계 비용으로 나누었다. 과거 고정 팔의 실패 대용 평균을 모형에서 뺀 차이는 손실 2%에서 -49.257467 ms(표본 5건)로 ±10 ms 기준을 벗어났고, 15%에서는 +1.545667 ms였다. 알려진 입력의 72문맥에서 행동 선택 변화는 0이었으며, T6 unacked+flight의 k2·RTT50·u2·p0.15·(0,3,1) 세계에서는 실패 조건부 비용과 참조의 차이는 -29.084599 ms였다. 앞 수치는 모형과 과거 trace 대조, 뒤 수치는 세계와 모형 대조다. 과거 고정 팔은 repeat_first이고 이 비용 참조는 당시 original_first를 가정했다. ACK·PTO·실제 CRYPTO 재전송의 비용을 연결할 관측이 충분하지 않아 두 단계 비용을 미채택으로 남겼고, 활성 비용식에는 넣지 않았다. 원자료 위치와 기준은 [참조 결과](J3%20두%20단계%20실패%20비용%20참조%20결과.md), 로컬 보존 `g3/v33/validation/J3_reference_v1/runs/J3_verify_v1.json`의 `comparisons[0]`·`comparisons[10]`·`contexts`·`decision_changes`에 있다. 세계 차이는 로컬 보존 `g3/v33/validation/J3_transport_v1/runs/J3_transport_full_v1/t6_unacked_flight_groups.json`의 `[3].conditional_initial_failure_ms`에서 앞 파일 `comparisons[10].model_ms`를 뺀 값이다.

## M4

개발 시뮬레이션 평가 과정에서 token·Retry·서버 지원 상태를 정책 입력으로 연결하는 후보를 검토했다. 기존 개발 전송 자료 168연결 중 156개를 캐시 재생했고, 첫 원본이 소거된 12개는 관측 재생에서 제외했다. 이는 새 성능 측정이나 168개 전부의 재생 성공이 아니다. 고정 팔의 전송 기능까지 검증했지만 실제 적응 정책 입력 훅, W1 평가, Go 정책 채택은 끝내지 못해 미채택으로 남겼다. 활성 적응 정책에 이 분기는 없고 보존된 `revisit-guard` 기능은 기본 off다. 원자료 위치는 [캐시 결과](M4%20재방문%20관측%20캐시%20결과.md), [고정 팔 기능 결과](M4%20고정%20팔%20전송%20검증.md)와 로컬 보존 `g3/v33/validation/M4_cache_v1/runs/M4_cache_verify_v1.json`의 `connections_considered`·`connections_replayed`·`missing_ticket_input`에 있다. 고정 팔 원자료는 로컬 보존 `g3/v33/validation/M4_guard_v1/runs/M4_guard_verify_v1.json`이다.

## J8

개발 시뮬레이션에서 서버 프로필과 하향 손실을 추적했다. 120조건 중 24조건에서 새 서버 송신 없이 서버 PTO 만료가 밀리는 사건 44개가 있었고 최대 이동은 192.184 ms였다. 이 값은 세계 타이머의 이동량이며 HCT 개선량이나 실제 전송 측정값이 아니다. 하향 손실 p_d>0의 비용 J는 None으로 남았고, 별도의 PTO 기준 진단에서도 W1 B7의 기존 판정은 바뀌지 않았다. 서버 관측 어댑터와 하향 손실 비용이 미검증이므로 후보는 미채택이며 활성 정책이나 동결 세계를 이 진단으로 바꾸지 않았다. 원자료는 로컬 보존 `g3/v33/validation/J8_downlink_v1/runs/J8_downlink_full_v1.json`의 `case_count`·`cases_with_no_send_postponement`·`no_send_postponement_count`·`max_postponement_ms`와 `g3/v33/V33FIX_world_diag_v1.json`의 `sections.j8_pto`이며, [하향 손실 결과](J8%20하향%20손실과%20서버%20타이머%20진단.md)와 [세계 기록 4절](v3.3.1%20세계%20시뮬레이터와%20판정%20통계.md)에 범위를 적었다.

## 루프 뒤 개발 평가

아래 두 후보는 위 14개를 묶은 뒤 최종 수정 단계에서 평가했고, 14개 집계에는 넣지 않는다. 둘 다 W0 세계 시뮬레이션이며 네트워크 측정은 없다. 판정은 같은 코드의 flag off(v3.2-dev와 같은 결정)를 같은 seed로 돌린 기준과 D47로 비교했다.

### CX1

개발 시뮬레이션에서 none 경로에 실현 후회 원장을 붙인 탐색을 평가했다. 원장에는 연결마다 0.05 ms를 쌓고 상한은 100 ms다. lead=0이고 무손실 J가 J_TIE 안에서 같은 후보 가운데, 지금 행동보다 바이트가 적고 EJ 차이가 원장 안에 드는 행동을 고른다. 탐색한 연결에서 y=1이면 실제 초과 HCT를, 실패면 T_PTO+RTT를 원장에서 뺀다. W1 15셀 20 seed의 조정 상한은 B10 0.236645 ms이고 나머지 14셀은 0이었다. B10 새 seed 51~130에서는 0.118972 ms였다. rate는 0.05, 0.1, 0.2 sweep 결과를 본 뒤 B10 여유가 가장 큰 값으로 골랐고 사전 등록이 없으며, 새 seed 반복은 B10만 했다. 무손실 B3_u0의 마지막 400연결은 서버 계수 10,489 B에서 3,840 B로, B4는 9,192 B에서 2,562 B로 줄었고 HCT 차이는 0이었다. flag off는 W1_raw_v32와 300/300 run에서 행동 수와 평균 HCT가 같았고, c1 경로는 켬과 끔이 300/300 run에서 같았다. 설계 단계 진단(도구로 다시 돌리지 않음)에서 지터 평균 10 ms 무손실 셀의 바이트는 10,484.1 B에서 10,393.8 B로 줄어드는 데 그쳤고, 손실 사건 한 번 뒤에는 원장 빚 때문에 수천 연결 동안 탐색이 멈췄다. 원장 상태에 따라 first flight 크기가 달라지는 방문 이력 노출 범위는 평가하지 않았다. 상태는 보류다. 기본값은 off이고, Python `decide3(explore=None)`과 Go `-p3-explore-rate-ms` 기본 0에서는 결정과 상태 JSON이 v3.2-dev와 같다. 어느 측정 계획도 이 플래그를 켜지 않아 실측 근거는 없다. 원자료는 [CX1 평가](../g3/v33/CX1_eval_v1.json)와 [평가 도구](../experiments/v33/cx1_eval.py)다. 결과 JSON의 `tool_sha256`은 REV-9에서 입력 경로 인자를 바꾸기 전 도구 판본이며 수치는 그대로다.

### AK1

개발 시뮬레이션에서 preflight ACK의 틈을 손실 우도로 쓰는 후보를 진단했다. 첫 원본은 ACK되지 않았는데 뒤 원본이 먼저 ACK되는 사건을 쓴다. 이 신호는 u>0, k>=2에서만 생기므로 B3_u0, B4의 고착은 풀지 못한다. 평균 차이는 B7 -3.565655 ms, B5 -0.660487 ms, B11 -0.443962 ms였으나 조정 상한이 B1 1.12474 ms, B2 2.01314 ms로 0.5 ms를 넘어 미확정이다. B12_c6000은 (0,1,3) 표가 없어 집계하지 못했다. 우도의 전멸 처리만 다른 앞선 변형은 B1 0.421606 ms, B2 0.004443 ms였으므로 결론이 우도 세부에 민감하다. 서버가 첫 원본 없이 뒤 원본을 먼저 ACK한다는 전제는 세계 모형의 동작이고 quic-go 실측으로 대조하지 않았다. 실제 클라이언트에는 ACK 범위를 정책 입력으로 넘기는 경로가 없다. AK1은 미채택이다. 원자료는 설계 단계의 스크래치 진단 출력이며 저장소에 보존하지 않았다.
