# L1 벤치 실행 범위

2026-11-02 정정: 이 실행의 정책은 L1 사본(상태 4)이고 none 모드는 HCT 3등급 우도로 배웠다. 지금 활성 정책 v3.3.1-dev(상태 11)는 C1 회신이 확인되기 전 목적지에 v3.2-dev와 같은 이진 우도·결정을 쓰고 범주 우도는 c1 경로에서만 쓰므로, 여기의 none 결과는 지금 none 경로의 결과가 아니다. 근거 `docs/v3.3.1 활성 정책 수정.md`, 지금 정책의 평가는 `docs/v3.3.1 W1 재판정.md`.

2026-10-30 KST에 L1의 Python 학습기와 독립 관측기를 구현했다. 이 문서는 전체 성능 판정 전의 실행 계약이다. 구현 시험과 짧은 실행이 통과해도 L1 완료나 정책 채택으로 보지 않는다.

정책은 `g3/v33/policy_snapshots/L1_v1`의 19개 Python 파일로 고정했다. 사본을 만들 때 원래 작업 트리와 파일 집합 및 바이트가 같은지 확인했고, 이후 벤치는 이 사본을 읽는다. 상태 버전은 4, 정책 버전은 v3.3-dev다. 이전 상태 버전은 거부한다.

원형 W1의 세계, 시드, 손실 일정, 참조 행동과 보고 문턱은 유지한다. 새 관측 계약은 `g3/v33/bench_overlays/L1_v1.json`에, 원형 입력의 검증 근거는 같은 폴더의 `L1_v1_import.json`에 있다. 원형 v31과 v32의 각 300개 실행 및 참조 19개를 원래 계약으로 검사한 뒤 연결한다. 기존 원자료의 protocol 지문을 새 값으로 바꾸지 않는다.

새 실행은 none, c1, ideal의 세 모드에 각각 15조건과 20시드를 적용한 900개 실행, 1,233,000연결이다. c1이 주 비교이며 none은 C1 없는 경로, ideal은 완전 수신 정보를 주는 진단이다. `L1_v1_execution_plan_v2.json`은 45개 shard와 동시 수집 8개를 명시한다. 각 수집기가 정책 worker 하나를 별도로 띄우므로 자식 프로세스 수는 최대 16개다. 각 작업의 시작 및 종료 기록, 표준 출력과 오류 로그를 인계 폴더의 runs 아래에 남긴다. 실행하지 않은 첫 계획도 보존했다. 둘째 계획은 실행 직전에 작업 목록과 명령을 재구성해 대조하고 저장 사본의 지문을 확인한다.

C1은 동결 전송 세계 위의 수동 관측 모형이다. 첫 실제 R 수신을 Handshake 시점의 대용으로 쓰고, 회신은 별도 난수로 손실을 겪는다. 회신 비용을 HCT, 증폭 예산, 다음 연결 간격에 넣지 않았다. 이 결과를 실제 와이어 C1의 효과로 해석하지 않는다. 회신 없음과 PTO만으로 전멸을 확정하지 않으며, 확인할 수 없는 관측은 3등급 경로로 보낸다. 이 기본값과 실제 계측의 잔여 범위는 결정 D13 및 D14, `L1 first flight 관측 계약.md`와 `runs/L1_c1_check.md`에 있다.

짧은 실행은 각 phase의 앞 네 연결만 사용하되 전체 W1의 연결 번호를 유지한다. 세 모드의 45개 실행, 312연결을 검사했다. 첫 cold 행동과 세계 비용의 모드 간 일치, 실행 receipt, trace 지문과 요약 재계산을 확인했다. 이 압축된 학습 이력은 성능 판정에 쓰지 않는다.

전체 수집 뒤 원형 600개와 새 900개의 행동 합집합을 하나로 고정하고 같은 세계에서 다시 평가한다. 기존 81행동의 신뢰구간을 새 집합에 그대로 붙이지 않는다. C1 대 v32의 전후 비교와 C1 대 v31의 비열등 판정을 구분한다. B1과 B2, 무손실 p 수렴 및 다른 조건의 0.5 ms/연결 악화 제한은 전체 자료로 확인한다. 새 정책의 성능 판정은 아직 미확인이다.
