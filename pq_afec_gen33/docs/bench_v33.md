# v3.3 독립 세계 회귀 벤치

`g3/v33/bench_protocol.json`이 시나리오, seed, 관측 경계와 판정 기준의 정본이다. 12개 가족을 15개 조건으로 나눠 seed 31부터 50까지 실행한다. B1은 2%→15%→2%, B2는 2%→25%→2%이며 각 구간은 450연결이다. B3와 B4는 1600연결, B5는 450+450연결이다. 구체 길이가 카드에 없던 나머지 정상 조건은 1350연결로 정했다. B8은 큰 인증서 16000 B를 사용한다. 이 값들은 기준 실행 전에 정한 프로토콜 선택이다.

`experiments/v33/bench.py`는 정책을 import하지 않는다. 세대·조건·seed마다 `python -I -B`로 `policy_worker.py`를 실행하고 JSON 줄로 결정과 관측을 주고받는다. 작업 디렉터리는 gen33이며, 과거 세대는 명시한 package 경로에서 읽기만 한다. 원본 패키지의 sys.path 삽입을 막고 실제로 읽은 모듈 경로와 SHA-256을 기록한다. worker는 파일 쓰기와 하위 프로세스 실행을 허용하지 않는다.

모든 seed는 빈 목적지 상태에서 시작한다. B9는 연결마다 상태를 비운다. 정책 입력은 W, 공개된 업링크 설정, 이전 관측으로 얻은 RTT다. 연결 뒤에는 HCT, 성공 여부, 관측 k, 수신 서버 바이트, 관측 RTT와 자기 행동·예측값을 전달한다. 참 손실률, 실제 인증서 선택, 세계 등급, 원시 도착 비트는 평가기만 보유한다. 같은 목적지 ID를 계속 써도 체인 정보는 ID에 들어 있지 않다.

RTT 이력은 Go cache의 규칙을 따른다. 성공 여부와 관계없이 유효한 RTT 표본의 최솟값을 쓰고, 아직 RTT가 없으면 성공 HCT 최솟값을 쓴다. cold 첫 결정에는 둘 다 없다. W0의 RTT 표본과 완료 뒤 바이트 관측 창에는 근사가 남아 있다. 이 벤치는 실제 RTT unavailable 빈도까지 재현하는 시험이 아니다.

세계, b0, 전역 고정 (0,3,1)은 같은 seed와 연결 번호를 쓴다. 인증서 혼합도 행동과 독립인 난수로 정한다. 서버 기준 추가 바이트는 연결 전체 서버 수신량에서 짝지은 b0 수신량을 뺀 값이다. 첫 비행의 서버 수신량과 클라이언트 송신량도 따로 기록한다. B4의 1855 B 문턱은 유지하며, 과거 p15의 첫 비행 계수와 연결 전체 계수가 같은 추정량이라고 해석하지 않는다.

```powershell
python -I -B C:\dev\pq_afec_gen33\experiments\v33\bench.py --dry-run --generations v31 v32
python -I -B C:\dev\pq_afec_gen33\experiments\v33\bench.py --smoke --generations v31 v32 --out C:\dev\codex_handoff\v33\runs\W1_smoke_new
python -I -B C:\dev\pq_afec_gen33\experiments\v33\bench.py --generations v31 v32 --out C:\dev\codex_handoff\v33\runs\W1_raw
```

스모크는 seed 하나에서 각 구간 네 연결만 실행하며 `mode=smoke`로 표시한다. 기준 성능표에 섞지 않는다. 본 실행은 세대당 411000연결이다. 각 seed의 결정 입력, 관측 입력, 결정 결과, 학습 결과와 평가용 참값을 gzip JSONL로 저장한다. 실패 연결도 평균에 포함한다. 요약 JSON에는 trace 해시, 세대 소스 감사, 행 수와 지표가 있다.

`--resume`은 같은 manifest와 완료 seed를 이어 쓴다. 프로토콜, 세계·실행기, 세대별 정책 소스가 다르면 거부한다. 기존 요약의 세대·변형·조건·seed·모드·프로토콜·행 수와 trace 해시도 검사한다. 불완전 trace는 지우지 않고 남기며, 다시 실행할 때 별도 파일을 만든다.

`guard_off`는 관측의 j_pred를 전달하지 않아 새 잔차 경보를 만들지 않는다. `reeval_off`는 worker 안에서 재평가 주기를 2^63으로 설정한다. 두 변형의 변경은 메모리에만 있고 원본 파일은 바꾸지 않는다. 원형 `full` 결과와 별도 이름으로 기록한다. 데이터그램 우도와 새 감시 설계는 후속 L 과제의 구현 대상이다.

`bench_metrics.py`는 seed를 통계 단위로 삼고 Student t 구간을 계산한다. 이미 변화 후 방향에 있던 사후 평균은 delay 0 탐지로 세지 않으며, 검출되지 않은 구간은 검열로 남긴다. 오경보 진단은 초기 100연결과 변화 뒤 100연결을 뺀 구간의 새 행동 경보 수다. B7·B8에서는 이를 원인이 확정된 손실 오탐률로 읽지 않는다.

독립 세계 oracle의 기대값은 별도 표본으로 계산한다. 같은 유한 표본에서 고른 최소값을 정확한 참값으로 취급하지 않는다. 작은 후회 문턱은 seed 구간, 공통 평가 오차와 최적 행동 선택 오차를 함께 반영한다. B6·B9의 주 oracle은 체인 혼합분포를 알고 행동을 정하며, 다음 체인 추첨값은 미리 알지 못한다.

W0에서 big-cert 15% 자동 행동의 꼬리와 Initial 재전송 비율은 사전 보정 기준 밖이었다. W1 결과는 이 사건 세계 안의 개발 회귀 결과이며 실제 네트워크 개선을 확인하는 측정 결과가 아니다.

## 독립 기대값과 집계

`oracle.py`는 정책 후보 생성기를 사용하지 않는다. 원본 데이터그램의 정수 증가분과 lead+T≤4의 전체 조합을 만들며, 세계가 정한 와이어 상한을 만족하지만 서버에서 잘리는 패리티도 후보에 남긴다. 선별은 64, 256, 1024, 4096, 16384개의 새 독립 표본으로 진행한다. 1024개 전에는 후보를 제거하지 않는다. 선택된 행동은 별도 seed의 131072개 표본으로 검증하며, 검증 결과를 보고 선택 행동을 바꾸지 않는다.

서로 다른 행동의 차이가 표본 안에서 일정하더라도 희귀한 차이가 없다는 뜻은 아니다. 이때 얻은 0폭 구간은 다른 행동을 제거하는 상한으로 사용하지 않는다. 검증 끝에도 이런 후보가 남으면 전체 최적값에 대한 선택 오차는 미확정으로 기록한다. 후보 수를 임의로 줄이거나 미확정을 0으로 채우지 않는다. 무손실 B3·B4에는 고정한 세계 소스와 모수에서만 성립하는 구조적 검산을 사용한다.

`bench_oracles.py build`는 문맥별 oracle을, `actions`는 실제 정책이 사용한 행동과 선택 기준 행동의 기대 차이를 계산한다. 실행 시간 예산은 체크포인트를 저장하는 단위이며 표본 수를 줄이는 기준이 아니다. 각 완료 결과에는 문맥, 모수, 소스 지문과 선택·평가 명세를 남긴다. 중간에 소스가 바뀌면 새 출력 폴더에서 시작한다.

`bench_report.py`는 seed별 행동 점유율로 기대 차이를 합친다. 같은 평가표를 여러 seed가 공유하므로 MC 오차는 seed 수의 제곱근으로 나누지 않는다. 절대 후회의 상한에는 선택 오차를 더한다. 같은 문맥을 쓰는 세대 간 직접 차이에서는 기준 행동 항이 상쇄되므로 선택 오차를 다시 더하지 않는다. 음의 차이 추정값도 그대로 보존한다.

보고 규칙은 `g3/v33/bench_reporting_rules.json`에 있다. seed 구간은 95% Student t 구간이고 MC 구간은 문맥 또는 평가 묶음 안의 99% 정규근사다. 둘을 합친 값은 모든 셀에 대한 동시 95% 보장이 아니다. `--allow-pending`으로 중간 보고서를 만들 수 있지만, 빠진 기대값을 실현 HCT로 대신 채우지는 않는다. 원자료, oracle, 행동 평가표의 식별자가 다르면 집계를 거부한다.
