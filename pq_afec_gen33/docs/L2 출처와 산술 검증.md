# L2 출처와 산술 검증

`l2_joint_artifact_check_v2.py`는 전체 계산과 보고의 완료 기록이 있는 자료만 검증한다. 3000실행과 150그룹, 210대조를 각각 대조하고, 행동 빈도를 유리수로 합쳐 공통 MC 오차를 다시 계산한다. seed별 평균·분산과 Student t 구간, 비열등 판정을 별도로 검산한다. 완성된 pool의 잠금을 잡은 동안 작업 시작·종료 기록과 체크포인트 연결도 대조한다.

EPS 검사는 새 L2와 고정 EPS의 gzip 관측 기록을 읽는다. 직전 Beta 상태와 결정 시점 사본, 등급별 예측 확률을 연결하고, 혼합 사후의 첫째·둘째 모멘트로 갱신값을 다시 계산한다. 모멘트 계산의 상쇄 오차를 줄이려고 평균이 큰 경우에는 여사건의 모멘트를 쓴다. 실제 손실 확률이나 예측 등급 확률을 새로 시뮬레이션하는 검사는 아니다.

기존에 검증한 독립 산술 helper의 SHA를 고정했다. 제품 정책과 보고기의 함수는 최종 산술 검사에서 호출하지 않는다. 검사기 준비 검토에서는 합성 전체 표와 기존 smoke 자료를 비교한다.

준비 검토에서 합성 산술 47639검사, 유리수 사후 모멘트 36조건, 기존 smoke 5실행·60관측의 545검사가 통과했다. MC 폭, 평균, 주 비교 표시, 비열등 상태를 바꾼 네 자료는 모두 거부했다. 첫 검사기는 B4의 필드를 `bytes`로 잘못 가정해 실패했고, 동결 보고기의 `server_extra_bytes`를 확인한 v2로 고쳤다. 실패한 v1 소스와 검토 실패 기록을 보존했다.

이 결과는 검사기 준비가 끝났다는 뜻이다. 실제 L2 전체 보고의 검사 결과와 채택 여부는 계산 완료 뒤 따로 기록한다. 원자료의 SHA 검증, 보고 산술 검증, 실제 네트워크 검증은 서로 다른 범위다.

계획 보존 묶음의 stdout 한 파일은 Git의 LF 저장 규칙 때문에 원본 CRLF 바이트와 달랐다. 원본 manifest를 별도 보존하고, 수정 manifest에 원본·저장본 SHA와 크기를 각각 기록했다. 실행에 쓴 원본 파일과 정책·보고 소스는 바꾸지 않았다.
