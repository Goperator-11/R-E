# T5 복호기 색인과 보관 한도

원본은 Initial이며 길이1472 B 이하인 datagram만 보관한다. 색인 키는 DCID, 연결 계정, CRC32, 원본 길이다. 전역512개, 같은 DCID와 계정에서64개를 넘으면 먼저 들어온 원본부터 제거한다. CRC가 같은 중복 원본도 각각의 수명과 순서를 유지한다. 수신 처리 때3초가 지난 최근 원본과1초가 지난 legacy 비행을 정리한다. 유휴 중 즉시 메모리를 회수하는 별도 legacy 타이머는 없다.

비행은 전역1024개, 같은 DCID와 계정에서8개로 제한한다. 상한에 닿으면 새 parity를 원래 datagram으로 넘기고 복호 기록은 만들지 않는다. 기존 비행을 축출해 다시 복원하는 중복 주입을 피하려는 기본값이다. legacy 심벌은 비행당32768 B, 전체 pending과 합쳐8 MiB로 제한하며 다음 입력과 복원 묶음을 위해65535 B를 남긴다. 이 상한은 프로세스 RSS가 아니다. 최근 원본과 메타데이터는 개수 상한으로 별도 제한한다. hold의 기존 D20 한도는 유지한다.

원본이 도착하면 같은 DCID와 계정의 비행만 찾는다. 각 비행의 원본은 CRC와 길이로 한 번씩 조회한다. 비행 수 상한8 아래에서 조회 작업은 O(k)이며 RS 산술 비용은 별도다. TTL 정리는 삽입 순서 목록으로, hold의 가변 수신 기한은 heap으로 처리한다. 만료 항목의 제거 비용은 그 기록의 수명 전체에 걸쳐 상각한다. 모든 비행의 보고용 집계는 주기 스냅숏에서만 수행한다.

A3-03의 모르는 DCID parity를 무조건 거부하는 제안은 적용하지 않는다. first flight 원본이 모두 유실되면 첫 수신 datagram이 정상 parity일 수 있다. 계정과 비행의 제한된 색인 조회 뒤 새 기록을 허용하며, 상한 초과 입력은 기록 없이 넘긴다. 이 경로의 전수 복호 검사를 유지한다. 출발지별 속도 제한이나 인증된 수신자만 허용하는 배포 정책은 이 테스트베드 변경 범위 밖이다.

같은 parity index의 재수신은 심벌을 덮거나 heldBytes를 늘리지 않는다. legacy는 raw datagram을 넘기고 hold는 기존 중복 폐기 규칙을 유지한다. 완료·CRC 실패·만료·종료 때 심벌 참조와 바이트 예약을 해제한다. 연결 계정이 다르면 같은 DCID와 CRC라도 원본을 공유하지 않는다.

비행이 이미 본 원본의 payload가 상한 때문에 밀려났다면 복호를 중단하고 decoder_evicted_source를 기록한다. 그 원본을 새 손실로 오인해 다시 주입하지 않는다. 비행을 만들기 전에 보관에서 사라진 원본까지 판별하는 기능은 없다. hold의 기록 정리 heap과 실제 소켓을 깨우는 heap은 구분한다. 복구가 끝난 비행의 TTL 정리 때문에 다음 소켓 읽기를 기다리게 하지 않는다.

검증은 실제 ReadFrom 전수 사례, 연결 간 분리, 상한·중복·TTL·종료 뒤 메모리 해제, 다른 DCID 비행1000개가 있을 때의 조회 횟수, Go race와 QUIC 기능 시험을 포함한다. 기능 시험의 실행 시간은 HCT 개선 근거로 쓰지 않는다. UDP OOB와 클라이언트 flush 변경은 별도 단계다.
