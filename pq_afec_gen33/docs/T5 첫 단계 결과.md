# T5 첫 단계 결과

출처는 구현·기능 검증이며 development다. 클라이언트의 peer·자체 발급 CID 검사와 최초 송신 경계, 계정 LRU·완료 후 10초 수명을 구현했다. T5 전체는 진행 중이다. DCID별 복호 색인과 UDP OOB 경로, A3-14 비행 대기 관측이 남았다.

Go 168개와 vet·race, 핵심 Python 351개·하위 548개가 통과했다. 기존 실제 ReadFrom700116사례·60설정도 통과했다. 이 전수 검증 뒤 바뀐 부분은 클라이언트 CID 생성기이며, 서버 영역·길이 파서·계정 수명과 hold 소스는 전수 검증 때와 같음을 바이트 단위로 확인했다.

실제 UDP 주입 시험의 6개 연결에서 다른 출처 12개와 다른 CID 6개를 거부했다. C1과 서버 바이트에는 정상 peer·CID만 들어갔고, Listener.Accept로 확인한 계정 6개가 10초 뒤 모두 만료됐다. 주기 스냅숏에는 전체 연결 표를 넣지 않았다. 단위 시험은 5000계정의 C1 회신과 LRU 상한, 만료 뒤 alias 정리, 충돌 CID의 모호성 유지, 동시 스냅숏을 확인했다.

기존 QUIC 기능 시험은 33연결 중 30성공과 의도한 업링크 전멸 3실패였다. 정상 입력에서 peer·CID·최초 송신 위반 계수는 모두 0이다. 실제 C1 사후 평균 6개가 Python과 정확히 일치한다. 정책 23개 파일은 T4 산술 관문 때와 같고, 공유 85파일에는 선언하지 않은 차이가 없다. 정책 산술은 바꾸지 않았다.

첫 UDP 주입 시험은 초기 SCID만 검사해 정상 CID 회전도 거부했다. 실패한 3행과 원래 로그를 T5_boundary_smoke_v1에 보존했다. 새 생성기는 연결이 발급한 CID를 최대 64개 등록한다. 다른 CID 주입의 허용 기준은 바꾸지 않았으며 두 번째 시험은 연결당 가짜 peer2개·CID1개만 거부했다. 최초 빌드의 시험 리터럴 타입 누락도 실패 stage와 로그에 남아 있다.

계정의 완료 시각은 평문 Handshake 헤더와 다르다. C1 자체는 여전히 인증되지 않은 부채널이고, 첫 헤더·CID 검사는 AEAD 검증이 아니다. 상세 한계는 docs/C1 신뢰 경계.md에 적었다. 경로 이동과 영 길이 CID, CID64개를 넘기는 장기 연결은 현재 테스트베드 범위 밖이다. 계정 상한에 의해 진행 중 자료가 축출되면 ConnAcctDropped를 올리고 warnings에 남긴다.

UDP OOB 래퍼를 바꾸면 고정 quic-go의 ReadBatch 경로도 복호기를 거쳐야 한다. sys_conn_oob.go의 대체 경로는 SyscallConn으로 직접 읽으므로 메서드 두 개만 노출하는 수정은 충분하지 않다. 원본 소스와 네 빌드의 자료 153파일·58921394B를 보존했다. X3에서 같은 블록 대조를 하기 전 경주 확률이나 HCT 효과는 미확인이다.
