## 한 번에 맞추기: `-profile sealed31`

v3.1 봉인 조건에 맞추는 비교에서는 gen33 서버와 클라이언트 양쪽에 `-profile sealed31`을 준다. 이 프로필은 아래 표의 "sealed31" 값을 설정한다. 같은 플래그에 다른 값을 명시하면 종료 코드 2로 거부한다(예: `-profile sealed31 -udp-path oob`). 같은 값을 명시하는 것은 허용한다. `-expect-k`는 명시한 값을 그대로 쓰고, 생략했을 때만 0(타이머만)으로 둔다. `-feedback`은 프로필이 정하지 않는다. C1 수집 대기를 늘리는 v33c1 클라이언트는 아래 개별 플래그 예외를 따른다. Go 기본값은 바꾸지 않는다.

봉인 v3.1 조건 재현. v3.1 3단계 봉인 러너는 로컬 보존본 gen31 `experiments/p21_gencompare.py`다(gen31 `g3/PROTOCOL_stage3.md` 5행). 이 러너의 `start_server`(2264~2280행), `run_client`(2323~2336행), 팔 표 `ARMS`(293~306행) 어디에도 `-feedback`이 없다. 공용 하네스 `experiments/g3bed.py`의 `start_server`(261~273행)와 `run_client`(346~362행)도 같다. gen31 `experiments`에서 `-feedback`을 넘기는 러너는 `experiments/p17_adaptive_value.py`(367행) 하나다. 그래서 재현할 때는 양쪽 모두 끈다. 아래 클라이언트 줄은 3단계 고정 팔 `g3fixL3`(m4L3, `ARMS` 298행)이다. 그 러너는 `-expect-k`를 조건의 k(ML-KEM 조건은 2), `-gap`을 50 ms(netem 대역 제한이 없는 조건은 8 ms), `-timeout`을 10 s로 명시했다(`profile` 274~278행, `TIMEOUT_S` 88행, `run_client`). `-expect-k`를 명시하면 sealed31은 그 값을 그대로 쓴다. 셀마다 다른 `-group`, `-uplink-mbps`, netem 조건은 러너의 셀 표를 따른다.

아래 Bash 예시의 `CERTSIZE`는 셀의 DER 목표 B, `CERT_PEM`은 해당 실행의 공유 PEM 경로, `UPLINK_MBPS`는 셀의 정책 입력 Mbps다. 서버의 인증서는 아래 "공통 인증서" 절대로 준비한다. `-group`, `-gap`, `-timeout`, `-n`과 netem은 계획한 셀 값으로 맞춘다. `-expect-k 2`는 ML-KEM 셀 예시이며 다른 셀에서는 그 셀의 k로 바꾼다. D50대로 기본 W는 1280 B이고 `-ips`를 주지 않는다(F31의 Initial 확대 팔 예외).

```bash
qamp -mode server -profile sealed31 -fec on -certsize "$CERTSIZE" -cert-file "$CERT_PEM" -stats server.json -conn-log conns.jsonl
qamp -mode client -profile sealed31 -fec on -layout v3 -m 4 -lead 3 -expect-k 2 -uplink-mbps "$UPLINK_MBPS" -gap 50ms -timeout 10s -n 200
```

## v33auto의 none·C1 팔

v33none은 C1 이력이 없는 별도 cache3를 쓰고 클라이언트 `-feedback`을 끈 auto3 팔이다. v33c1은 서버와 클라이언트 양쪽에 `-feedback`을 켠 auto3 팔이다. 두 팔 모두 `-expect-k <셀의 k>`와 `-uplink-mbps <셀 값>`을 명시한다. auto3은 uplink 생략을 종료 코드 2로 거부하며, 0은 무제한 링크의 직렬화 비용 0을 뜻한다. 정책은 이 값을 추정하지 않고 참값으로 입력받는다. 실제 입력은 각 행의 `policy_uplink_mbps`에 기록한다(CP-02).

`arrivalEvidence`는 클라이언트 `-feedback`이 꺼져 있으면 `arrivals.src=none`, `c1.reason=disabled`를 돌려준다(`experiments/quicbed/observation.go`). 이미 켜진 `c1_seen`은 이 플래그로 지워지지 않는다. none 경로를 재려면 C1을 받은 cache3를 재사용하지 않는다. C1 이력이 없는 목적지의 관측·결정 일치 범위는 `docs/v3.3.1 활성 정책 수정.md`를 따른다.

v33none의 ML-KEM 셀 클라이언트 예시:

```bash
qamp -mode client -profile sealed31 -fec auto3 -cache3 c3_none.json -feedback=false -expect-k 2 -uplink-mbps "$UPLINK_MBPS" -gap 50ms -timeout 10s -n 200
```

v33auto 학습 팔인 v33c1은 클라이언트에서 `-profile`을 빼고 `-retrans-layout repeat_first -client-tracer=false -expect-k <셀의 k>`를 개별로 준다. C1은 표준 QUIC에 없는 서버 회신이다. 서버는 client Handshake datagram을 받아야 회신하므로, 1-RTT 연결의 C1은 HCT 뒤 약 한 RTT를 더 지나 도착할 수 있다(`experiments/quicbed/observation.go`의 `feedbackLocked`). RTT 200 ms에서 200 ms 대기만 두면 회신을 놓칠 수 있다. `sealed31`은 다른 `-feedback-wait`를 거부하므로 클라이언트만 개별 플래그를 쓴다(MS-06).

대기 한도는 셀마다 `max(200 ms, 2.5×RTT)`로 고정한다. S_rtt200은 500 ms다. 같은 셀의 C1 수집 팔끼리는 같은 한도를 쓰고 결과를 본 뒤 바꾸지 않는다. 서버에는 `-profile sealed31 -fec on -feedback`을 유지해 basic 경로와 C1 판본 2를 쓴다. `-feedback-version`은 서버 전용이다. 아래는 S_rtt200의 k=2 예시다.

```bash
qamp -mode server -profile sealed31 -fec on -feedback -certsize "$CERTSIZE" -cert-file "$CERT_PEM" -stats server_c1.json -conn-log conns_c1.jsonl
qamp -mode client -fec auto3 -cache3 c3_c1.json -feedback -feedback-wait 500ms -retrans-layout repeat_first -client-tracer=false -expect-k 2 -uplink-mbps "$UPLINK_MBPS" -gap 50ms -timeout 10s -n 200
```

v33none은 회신을 기다리지 않는다. v33c1의 HCT 뒤 대기는 연결 사이 간격과 수신 관측 구간을 바꾸므로 이 둘을 봉인 v3.1과 완전히 같은 조건이라고 부르지 않는다. `server_bytes`에는 대기 중 받은 비회신 datagram도 들어간다. X6 S_rtt200에서 가장 많이 고른 행동은 v33none이 (0,2,2) 2,371/2,400행, v33c1이 (0,3,1) 2,275/2,400행이었다. 대기 중 비회신 datagram이 S 추정을 키운 것이 원인으로 보이며 직접 증거는 타이밍과 결정 재생이다. 영향의 크기는 [X6](X6_result.md)의 C1 대 none 값을 본다. 수정 뒤 정책 입력은 server_bytes_pre_wait이고 server_bytes는 전체 값으로 남는다. 비용 모형·W0는 실제 C1의 바이트·처리 비용·다음 연결까지의 대기를 청구하지 않는다(`docs/L1 first flight 관측 계약.md`).

러너는 gen33 모든 행의 `flight_expectation.source == "explicit"`와 `flight_expectation.k == 셀의 k`를 확인한다(MS-07). smoke의 S_rtt200 v33c1은 `feedback_wait_limit_ms=500`과 셀 전체 `feedback_wait_received` 비율 0.85 이상을 확인한다. X6 본측정에서는 `feedback_received_rate_by_class`를 one_rtt 분류별로 보고하고, 행이 20개 이상인 부류의 수신률이 0.95 미만이면 그 셀을 C1 경로 측정에서 제외했다고 표시한다. 실제 smoke와 본측정 검사는 후속 측정 카드에서 수행하며 이 문서의 플래그 설명을 통과 결과로 세지 않는다.

실행 기록에서는 클라이언트 행의 `profile`(sealed31일 때만 생긴다), `policy_uplink_mbps`, `feedback_wait_limit_ms`, `feedback_wait_received`, `retrans_layout`, `observation.tracer`, `flight_expectation`, `arrivals.src`를 본다. 서버 stats에서는 `profile`, `udp_path`, `feedback_version`, `fb_sent`, `certificate`를 확인한다.

## 공통 인증서

측정 셀마다 gen33 동결 바이너리로 `qamp -mode certgen -certsize "$CERTSIZE" -cert-file "$CERT_PEM"`을 한 번 실행한다. `CERT_PEM`은 로컬 보존 측정 원자료 폴더 `~/v33_runs/<id>/certs/cert_N.pem` 안의 경로로 정한다. 팔마다 포트와 서버 프로세스를 나누되 같은 gen33 서버 바이너리와 같은 셀의 PEM을 쓴다. 서버에는 항상 `-certsize "$CERTSIZE" -cert-file "$CERT_PEM"`을 함께 준다. DER 목표가 기본값 2955 B와 다른데 `-certsize`를 생략하면 파일 길이 검사에서 종료 코드 2로 거부한다(`experiments/quicbed/certificate.go`).

동결 클라이언트도 이 gen33 서버에 붙인다. 결과에는 "봉인 측정과 서버가 다르다"고 적는다. 각 세대의 자기 서버를 쓰는 MS-18 비교는 별도 조건이다. 결과의 `checks.server_uniform`은 셀마다 `certificate.der_sha256` 값 하나, `certificate.der_bytes == certsize`, `server_binary_sha256` 값 하나인지 확인한다(MS-18 제외). PEM에는 개인키가 있으므로 위 certs 폴더 밖으로 꺼내거나 저장소에 넣지 않는다. 공개 결과에는 크기와 SHA-256 등 식별 정보만 남긴다. 공유 인증서로 CertificateVerify 길이 변동이나 서버 first flight의 모든 바이트·시간이 같아지는 것은 아니다(`docs/T1 고정 인증서 결과.md`).

## retrans-layout 기본값을 repeat_first로 되돌린 이유

D28은 v3 응답 전 후속 묶음의 기본 모양을 `original_first`(원본 먼저, 뒤 XOR parity 1개)로 바꿨다. auto3의 비용 모형(`layout.evaluate`, Go `p3Evaluate`)은 이 추가 재전송 보호를 반영하지 않는다(`docs/T6 후속 Initial 묶음 계약.md`). 이 조건에서는 X6의 L1 효과와 재전송 모양 효과가 섞이므로 D43에서 기본값을 `repeat_first`로 되돌렸다. `original_first`는 `-retrans-layout original_first`로 명시할 때만 쓴다. 이 문서에서는 정책 산술이나 기본값을 바꾸지 않고 J3·J4를 재개하지 않는다.

## 공통 서버에서 세대를 섞을 때의 규칙

동결 클라이언트(gen-2 `d98b05d7`, v3.1 `g3c_6baf2b52`, v3.2 `gen32_85f54cf5`)의 `parseFeedback`은 판본 2이고 길이가 `12+4*nc`와 정확히 같을 때만 회신을 받는다. 받지 못한 회신은 클라이언트 쪽 `-feedback` 설정과 상관없이 `countRx`로 들어가 `server_bytes`에 더해진다(gen31 qamp.go 1216~1223행). gen33 서버가 비행의 FEC 틀만 보고 클라이언트 세대를 가를 수는 없다. 틀 판본 1(v2 배치)은 gen-2·v3.1·v3.2·gen33이 모두 쓰고, 판본 3(v3 배치)은 v3.1·v3.2·gen33이 함께 쓴다(각 qamp.go의 `fecVer`·`fecVerLead`). FEC를 끈 팔은 틀 자체가 없다. 그래서 서버 플래그로 정한다.

1. 동결 클라이언트가 하나라도 붙는 gen33 서버에서 `-feedback`을 켜면 `-feedback-version 2`(또는 `-profile sealed31`)를 준다. 판본 3 서버에 동결 클라이언트를 붙인 결과는 비교에 쓰지 않는다.
2. 판본 2에서도 gen33 클라이언트의 `arrivals`(src·sent·lost·bitmap·trunc)는 판본 3과 같다. 달라지는 것은 진단 행 `c1.recovered_original`이 0이 되는 것뿐이다. 판본 3의 복원 CRC 진단이 필요하면 gen33 클라이언트만 붙는 서버를 따로 띄운다.
3. 실행마다 서버 stats의 `feedback_version`과 `fb_sent`를 기록하고 확인한다. `-feedback`을 켠 서버(`fb_sent` > 0)가 판본 3이고 동결 클라이언트 팔이 있으면 그 블록은 버린다. `-feedback`을 끈 서버는 회신을 보내지 않으므로(`fb_sent` 0) stats에 `feedback_version` 3이 남아 있어도 이 규칙으로 버리지 않는다. 묶음 B loopback의 `fixed_nofeedback` 서버가 이 경우다(`docs/v3.3.1 Go 테스트베드 수정.md` 부록 A, `srv_fb_sent 0`, `srv_feedback_version 3`).
4. 기존 하네스처럼 팔마다 서버와 포트를 따로 띄우면 이 규칙이 필요 없다. 봉인 v3.1 3단계 러너(gen31 `experiments/p21_gencompare.py`)는 `-feedback`을 쓰지 않았고, 팔마다 슬롯(포트)을 나눠 서버를 따로 띄웠다(`ARMS`의 `slot`, `SERVERS_DEFAULT`·`SERVERS_S1`). 감사 F1 검증 의견도 공용 하네스 `g3bed.start_server`를 두고 같은 결론을 냈다.

이 규칙의 근거 시험과 loopback 결과는 `docs/v3.3.1 Go 테스트베드 수정.md` F1 절에 있다.

## 연결별 서버 기록: `-conn-log`

`-conn-log 경로`는 새 파일을 만들고(이미 있으면 종료 2), 계정이 만료·LRU 축출될 때와 SIGTERM·SIGINT 종료 직전에 연결마다 JSON 한 줄을 쓴다. 각 줄은 기존 `conns` 값과 같은 필드에 `key`, `reason`(`expired`·`lru`·`shutdown`), `logged_ns`를 더한 것이다. 연결당 정확히 한 줄이다. 계정 수명(완료·종료 뒤 10 s) 때문에 `expired` 줄은 연결이 끝나고 약 10 s 뒤에 생긴다. 서버를 SIGKILL로 죽이면 아직 쓰지 않은 줄은 잃는다. 서버 stats의 `conn_log`에 기록 줄 수·오류 수·대기 수가 남는다. T7 러너는 서버를 SIGTERM으로 끝내고 이 파일을 읽는다. 기본값은 꺼짐이고 끄면 기존 동작과 같다.

## 아직 재지 않은 것

- 클라이언트 qlog tracer의 비용. 같은 블록에서 `-client-tracer`만 다른 A/A 비교는 재지 않았다. X9는 두 팔 모두 켰고 X1은 모두 껐으므로 팔 간 비교에는 섞이지 않는다. tracer를 켠 팔과 끈 팔의 HCT를 섞어 비교하지 않는다.
- `-conn-log`의 서버 CPU 비용. 100 ms마다 만료 처리와 JSON 인코딩을 한다.
- udp-path basic과 oob의 HCT 차이(X3). 이 연구 범위에서 재지 않았으므로 oob 경로의 경주 표는 미검증이다.
- sealed31로 돌린 gen33과 동결 v3.1의 일치는 [M1](M1_result.md)에서 bigcert 2%, 고정 m4L3로 쟀다. 동결 v3.1 클라이언트 빼기 gen33 클라이언트(b_c)는 -0.372300 ms [-1.850523, 1.105923], 같은 설정 A/A(c_d)는 -0.001693 ms [-1.188556, 1.185171]이다. 다른 셀과 auto 정책으로 넓히지 않는다.
