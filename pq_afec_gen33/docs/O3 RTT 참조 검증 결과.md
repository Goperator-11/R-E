# O3 RTT 참조 검증 결과

Python 참조를 검증했다. 새 시험 70개, 기존 시험 351개와 하위 검사 548개가 통과했다. 활성 L1 상태 4와 Go·세계 코드는 바꾸지 않았다. O3는 partial이며 실제 관측 연결과 채택 관문이 남아 있다.

## RTT 계산과 관측 범위

`experiments/v33/rtt_reference.py`는 귀속을 확인한 ACK 표본의 직렬화·shim 대기·적용 가능한 ACK 지연을 뺀다. 한 연결에서 나중 무대기 1-RTT 표본을 우선하고, 없으면 귀속이 확인된 Initial 표본을 쓴다. 연결 전체의 MinRTT를 특정 패킷의 RTT라고 가정하지 않는다. 미확인 업링크나 바이트는 결측으로 남긴다.

50 ms를 학습한 뒤 100 ms 표본 8개를 넣으면 EWMA는 94.99435424804688 ms다. 150 ms 표본 8개에서는 139.98870849609375 ms이며, 최소값 50 ms는 별도로 남는다. 이 값은 합성 계단의 산술 결과다. 실제 경로가 8연결 안에 이만큼 추종한다는 측정 결과가 아니다.

고정 quic-go의 `rtt_stats.go`는 MinRTT를 원시 sendDelta로 저장하고, LatestRTT에서는 조건에 따라 ACK 지연을 뺀다. `sent_packet_handler.go`는 Initial·Handshake ACK의 지연 필드를 쓰지 않는다. 이 구분을 누락했던 참조의 첫 시험을 보강했고, Initial의 양수 ACK 지연 입력을 거부한다. 첫 시험 69개와 후속 70개 기록을 모두 보존했다.

T4의 RTT200 진단 9연결과 T6의 12연결에는 유효 RTT 표본이 없었다. PTO가 먼저 outstanding packet 기록을 없앤 뒤 ACK가 도착한 경로다. 이 연결에 계산으로 만든 RTT를 넣지 않는다. 현재 `observation.go`는 qlog RTT 갱신과 ACK 범위를 저장하지만, 원시 RTT의 소유 패킷·ACK delay·실제 대기량을 완전히 연결하지 않는다. 다음 단계는 이 관측 공백을 줄이는 것이다.

## 지터 진단

seed31~50을 고정하고 각 seed에서 32연결을 준비한 뒤 2,000문맥을 평가했다. 세 조건의 평가 문맥은 120,000개다. 경로 RTT는 양수 하한 0.1 ms를 둔 Gaussian 표본이며, 같은 경로에서 1-RTT HCT와 2-RTT HCT를 각각 만들었다. 분류에는 현재 표본을 반영하기 전 추정값을 썼다. 실제 네트워크나 W1 결과가 아니다.

| 평균 RTT·표준편차(ms) | EWMA만 사용한 1-RTT 오분류율 | 변동 4배 여유의 1-RTT 오분류율 | EWMA만 사용한 2-RTT→1-RTT 비율 | 변동 4배 여유의 2-RTT→1-RTT 비율 |
|---|---:|---:|---:|---:|
| 20·5 | 0.011900 | 0 | 0.249350 | 0.807525 |
| 50·10 | 0.007625 | 0 | 0.142675 | 0.698300 |
| 50·20 | 0.110125 | 0.000300 | 0.298425 | 0.841100 |

여유를 늘리면 지터로 늦은 1-RTT를 덜 잘못 분류하지만, 실제 2-RTT도 많이 가린다. 이 결과를 학습 개선으로 해석하지 않는다. 4배를 결과에 맞춰 줄이지 않았고, 현 참조를 활성 분류기에 연결하지 않았다. C1 물리 도착 우도와 HCT 등급의 역할을 구분하고, 겹치는 경계의 불확실성을 다음 설계에서 다뤄야 한다.

## 과거 저널 재집계

감사 원본 `verify-A1/v07_rtt.py`와 `audit-quicgo-source/p02_scan.py`를 import 경로만 gen33으로 옮겨 재실행했다.25개 저널 124,800행에서 정책 RTT의 최초 55.945218 ms, 최소 50.6713 ms, 중앙 50.739046 ms를 재현했다. 2 Mbps·RTT50 ms의 lead0·1·2·3 연결별 부풂 중앙값은 각각 6.02·11.27·16.77·22.35 ms로 원문의 반올림 값과 같았다.

별도 재집계에서 성공하고 RTT가 유효한 행은 102,440개였다. lead·ips_eff·parity 바이트를 모두 쓸 수 있는 44,656개만 `ips_eff + lead * 평균 패리티 바이트`의 직렬화를 빼 보았다. 나머지 57,784개는 입력 부족으로 남겼다. 예를 들어 고정 팔의 ips_eff0을 실제 1280 B로 자동 대체하지 않았다.

| RTT·업링크·g3auto lead | 근사 보정 행 수 | 보정 후 편향 중앙값(ms) | ±1 ms 범위 |
|---|---:|---:|---|
| 50 ms·2 Mbps·0 | 2,206 | 0.899143 | 범위 안 |
| 50 ms·2 Mbps·1 | 2,524 | 0.826399 | 범위 안 |
| 50 ms·2 Mbps·2 | 1,990 | 0.992885 | 범위 안 |
| 50 ms·2 Mbps·3 | 7,514 | 1.218446 | 범위 밖 |
| 50 ms·2 Mbps·4 | 66 | -2.562712 | 범위 밖 |
| 200 ms·2 Mbps·2 | 56 | 1.141458 | 범위 밖 |

이 표는 MinRTT의 ACK 소유권을 확인하지 못한 근사다. 손실로 선행 바이트 일부를 기다리지 않은 표본이나 나중 표본에 같은 first flight 보정을 적용하면 과도하게 뺄 수 있다. 모든 팔의 실측 ±1 ms 관문은 충족하지 않았다. 처리 시간 상수를 새로 맞춰 범위에 넣지 않았다.

## 검증과 후속

`runs/o3_reference_verify_v1.py`가 합성 원자료 121,920행, 평가 문맥 120,000개에서 720,000개 등급 판정, 과거 124,800행과 44,656개 근사 보정을 별도로 검산했다. EWMA·변동·경계는 참조 모듈을 import하지 않고 다시 계산했다. 원자료 SHA-256과 활성 소스 14개의 불변도 확인했다.

전체 W1, 보정 표본의 실제 수집, Go 거울, 활성 상태 변환은 아직 실행하지 않았다. 다음 반복은 귀속 가능한 표본의 수집 경로를 읽고 보강하는 단계다. D34의 결과와 입력 한계를 보존하며, 단위시험 통과를 채택 근거로 대신하지 않는다.
