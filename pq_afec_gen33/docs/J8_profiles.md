# J8 서버 프로필 참조 결과

반복58, 모형 계산이다. 실제 서버 성능이나 활성 정책 개선을 뜻하지 않는다. J8은 partial이며 전체 J3 비용과 하향 재전송 시간 연결이 남았다.

ServerProfile은 mode, P, iw_pkts, pto_initial_ms, lead_credited, trailing_race를 검증한다. 첫 서버 데이터그램 크기는 잠정 P 관측으로 남기고, 모든 모드 추정 조건이 충족되어도 계획에는 exact를 유지한다. 서버 수요·하향 손실·주소 검증·창 제한·후속 신용이 모드 추정을 흐리지 않도록 별도 입력으로 둔다. 계약은 docs/J8_server_profile_contract.md다.

88개 시험과41개 하위 검사가 통과했다. 동결 W0와 P3개·mode3개·IW3개·k2개·lead3개·서버 패킷 수3개·마지막 크기2개의972조건에서 첫 서버 송신 크기 목록이 모두 일치했다. 이 대조는 무손실·업링크 무제한·사전 ACK 없음·결정 지연0의 고정 조건이다. 이 조건을 전체 HCT 적합성으로 확대하지 않는다.

하향 첫4개 손실을 강제한3개 모드에서는 주소 검증 전 송신과 재전송을 누적 예산으로 별도 재생했다. 참고 예산 계산에서 신용1600 B, 첫 송신3840 B, 손실2개이면 exact는 추가0 B, granular는1280 B까지만 허용하고 다음1280 B는 막힌다. unlimited는2560 B를 허용한다. 이는 ACK·혼잡 회복·타이머를 생략한 예산 비교다.

서버15패킷이 모두 도착할 확률은 하향 손실1%에서0.860058355,2%에서0.738569103,5%에서0.463291230다. 이 비율을 지연 이득의 감소율로 사용하지 않았다.

기존 핵심351시험·548하위 검사 영수증의 모든 소스·로그 해시가 유지됐다. 활성 L1·상태4·Go·동결 W0를 바꾸지 않았다. 이번 참조는 활성 정책 호출 경로에 없으므로 W1 전후 성능 차이는 측정하지 않았다. 전체 비용을 연결할 때 고정 seed와 B1·B2 검증을 이어간다.

검산기v1은 worldsim.py의 동결 해시를 worldparams.json과 비교해 실패했다. 두 파일 모두 변경되지 않았음을 확인한 뒤 v2에서 대상 경로를 바로잡았다. 실패 스크립트와 실패 기록을 보존했다. 정책·세계·시험 기준은 바꾸지 않았다.

다음 반복은 서버 첫 비행의 정확한 바이트 목록을 J3 복구 참조에 전달하고, p_d 분기에서 첫 서버 응답·주소 검증·재전송 대기·이미 쓴 예산을 분리한다. 동결 W0의 시간 사건과 비교하며 불일치를 계수 조정으로 없애지 않는다.

## 반복59 프로필별 복구 비용

하향 무손실 범위에서 ServerCost를 J3 복구 참조의 성공·첫 재전송·강제 종료에 연결했다. 활성 정책은 그대로다. p_d>0은 J=None·cost_complete=false이며 시간 비용을 행동 점수로 사용하지 않는다. 첫 서버 데이터그램이 손실 없는 주소 검증 응답을 가능하게 한다는 근사, 고정 IW, 첫 응답 W B와 이후 ACK41 B의 직렬화를 명시했다. 실제 혼잡 창 성장·후속 손실·타이머 소유권은 이 일치 결과의 범위 밖이다.

152개 시험이 통과했다. 프로필이 없는960조건의 결과 전체가 이전 커밋의 함수와 정확히 같았다. 같은200.86 ms·granular·P1280·IW32로 명시하면 기존 복구 비용도 유지된다. 명시적 quic-go 프로필은 카드대로 초기 PTO200 ms이며 이전 실측 상수와 구분했다.

동결 W0의 무손실1,620조건에서 HCT와 참조의 최대 절대 차이는2.27373675443232e-13 ms였다. P3개·회계3개·IW3개·k2개·S3개·u2개·고정 행동5개를 비교했고 처리 지연·경주 지연·재전송 타이머를 껐다. 이는 이 제한 조건의 산술 대조다. W0 파일과 기본값을 바꾸지 않았다.

18문맥·8프로필의144선택에서6,045후보를 평가했다. k는 고정이며 후보는0·1 B·크기 상한·프로필의 첫 비행 신용 경계로 제한했다. 모든 정수 delta의 전역 최적이나 현재 ClientHello의 재패킷화를 확인한 것은 아니다. 동률창은 기존0.01 ms를 유지했다. quicgo 선택과 달라진 수는 다음과 같다.

미지원 선행 바이트를 보관 패리티로 잘못 표시하지 않도록 ignored_lead와 held를 분리했다. 하향 미해결 분기의 지연 기여와 실패 조건부 비용도 None으로 표시하고 무손실 반사실 필드에 보존했다. 검산기v1의 로그 경로 필드 가정 오류는v2에서 실제 영수증 형식에 맞췄고 실패 기록을 남겼다. 진단v1의 예상 세계 사례 수648은 식에 고정 행동5개를 반영한v2에서1,620으로 바로잡았다. 실제 조건·세계·문턱은 변경하지 않았다.

전체 하향 재전송 시간과 주소 검증, 실제 P/모드 관측 연결, 전체 W1 활성 채택은 미완료다. 다음 반복에서 손실 패턴별 서버 송신·ACK·타이머 사건을 고정 입력으로 추적한다.
