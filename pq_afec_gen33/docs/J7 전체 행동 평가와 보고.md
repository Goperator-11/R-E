# J7 전체 행동 평가와 보고

기존 J7_evaluation_plan.md와 수집 계획은 그대로 둔다. 이 문서는 전체 수집을 마친 뒤 그 계획을 실행하는 분석기의 범위를 설명한다. 후보 성능을 판정하기 전에 작성했다.

bench_j7_family.py는 2개 세계 프로필, 2개 정책, 3개 관측 방식의 전체 자료를 읽는다. 각 실행의 완료 기록과 해시를 확인하고 모든 연결의 행동 빈도, 손실 일정, 관측 입력과 RTT 이력, 요약을 재검산한다. 그 자료에 등장한 문맥과 행동의 합집합을 한 가족으로 고정한다. 세계 프로필의 문맥 ID는 서로 다르다. 같은 물리 문맥을 두 세계에서 잘못 합치지 않는다.

두 프로필의 시나리오를 합친 MC 전용 프로토콜은 기존 시나리오 ID 앞에 프로필 이름만 붙인다. 각 시나리오의 세계 매개변수와 seed, 손실 일정은 동결 수집 계획 그대로다. 원래 W1 프로토콜을 덮어쓰지 않는다.

공통 비교 행동은 W1에서 이미 고정된 참조 행동이다. 39 B의 참조 파일을 원래 수입 기록의 해시와 대조하고, 같은 문맥의 46 B 세계에서도 그 행동을 고정 비교 기준으로 쓴다. 46 B에서 다시 선택하거나 최적이라고 간주하지 않는다. 각 세계 안의 두 정책 차이에서는 같은 문맥의 참조 비용이 상쇄된다. 39 B의 무손실 증명을 46 B로 옮기지 않으며, 기존 oracle.py가 해당 세계에서 허용한 증명만 쓴다.

기존 bench_action_pool.py와 oracle.py는 수정하지 않았다. 표본은 행동마다 131072개, 평가 seed는 850001, 작업자는 8개다. 증명으로 끝난 행동만 표본 수가 0이다. 중간 체크포인트를 보존하고 고정 표본까지 이어가며 결과에 따라 표본 수나 행동 목록을 바꾸지 않는다. 전체 가족 크기로 보정한 기존 정규 근사 오차를 쓴다. 다른 행동의 표본 차이가 수치상 영분산이면 동등하다고 단정하지 않는다.

bench_j7_report.py의 주 결과는 같은 세계에서 J7에서 L1을 뺀 기대 비용 차이다. seed별 행동 빈도는 유리수로 계산한다. 각 셀은 seed 단위 Student t 95% 구간에 공통 MC 오차를 합친다. MC 오차는 seed 수의 제곱근으로 나누지 않는다. 두 세계의 none과 c1, 각 15개 시나리오를 합친 60셀 모두 상한 0.5 ms/연결 이하이며, C1 셀 중 하나 이상에서 상한이 0 미만이어야 성능 조건을 통과한다. ideal이나 다른 셀의 감소가 실패한 주 셀을 상쇄하지 않는다.

와이어 프로필 효과와 두 요인이 함께 바뀐 끝점은 기대 비용의 점추정으로 분해한다. 참조 비용이 상쇄되지 않는 서로 다른 세계의 비교이며, 그 차이의 공통 MC 구간은 계산하지 않았다. 이 점추정과 실현 HCT 구간은 기여를 살피는 진단으로만 저장한다. 이 자료로 새로운 세계의 절대 최적 후회나 채택을 판정하지 않는다.

validate_j7.py는 생산 분석기의 집계 함수를 부르지 않고 원자료에서 행동 빈도와 합계, p 편향, 관측 경계를 다시 계산한다. 각 손실 구간의 첫 연결과 마지막 연결을 고정 seed로 재생해 세계 결과와 관측기 출력을 대조한다. 보고 검사는 validate_j7_v2.py가 원자료에서 구한 유리수 빈도와 MC 체크포인트 모멘트를 사용한다. Student t와 정규 분위수는 별도 SciPy 구현으로 대조한다. 전체 원자료를 다른 세계 구현으로 재현하는 검사는 아니다.

최초 보고 검사기는 MC에도 seed 구간의 95%를 적용해 실패했다. 동결 W1 프로토콜의 MC 신뢰수준은 99%다. 원자료와 보고서는 그대로 두고 v2 검사기가 그 고정 값을 읽도록 정정했다. 최초 검사기와 실패 기록도 보존한다. 판정 기준을 바꾼 것이 아니며, 보고 검사에는 v2를 사용한다.

전체 정책·L1 보충 관문과 와이어 시험은 성능 관문과 따로 통과해야 한다. 파일과 결과는 개발 시뮬레이션 자료이며 실제 QUIC 측정이나 확증 결과가 아니다.
