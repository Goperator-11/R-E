baseline의 85건은 저장된 obs_y로 계산했다. 과거 replay31.py의 86건은 학습기를 재생한 별도 통계여서 섞지 않는다.

처리 상수의 근거는 2% (0,3,1) 자동·고정 합산 6,622행의 1RTT 조건부 관측-모형 차이 2.610030 ms다. 자동 팔 2.406377 ms와 고정 팔 3.003452 ms도 JSON에 구분했다. 2.6 ms를 조건마다 똑같이 측정한 상수로 해석하지 않는다.

15% 고정 L3의 실패·재전송은 130/2,250, 조건부 평균 266.392615 ms다. 모형의 실패 조건부 비용은 233.444486 ms, 전체 연결당 기여 차이는 +1.209821 ms다. 자동 팔은 114/2,405, 조건부 평균 269.955763 ms, 기여 차이 -1.385513 ms다. 자동·고정 합산에서 차이가 상쇄된다는 것만으로 실패 비용의 정확성을 주장하지 않는다.

꼬리 HCT 전체를 더한 2.81/7.64 ms는 초과 지연의 정의가 아니다. 이번 표에서는 정상 2RTT 평균을 뺀 검증자 정정값을 썼다.

GE 계산은 기존 layout의 도착 패턴·경주·비용식을 재사용한 model-world 재현이다. W0 독립 세계 검증이 아니다. iid 240조건의 기존 evaluate와 최대 차이는 5.6843418860808015e-14 ms다. J3 분해 합의 최대 오차는 5.0626169922907138e-14 ms다.

서버 수신 바이트는 server_delta를 합산하고 실제 반환 연결 수로 나눴다. 손실이 있는 조건에서는 클라이언트 송신 바이트로 해석하지 않는다. 최초 비행 송신량은 별도 열이다. 전체 실행·손실률·마지막 블록별 182행을 server_accounting.csv와 JSON에 남겼다. 필수 계수 누락은 없었다.

전체 실행과 마지막 블록은 다르다. p11 l0 마지막 블록의 서버 수신량은 gen2 7,235.4 B/연결, gen3 10,551.3 B/연결로 실행 전체와 비교 방향이 뒤집힌다. RTT200 Initial 계수는 연결 전체 값이며 최초 비행 크기가 아니다. unavailable의 원인은 이 집계만으로 확정하지 않는다. RTT200 HCT 구간별 빈도는 성공 연결만 세고 hct_ms 통계는 전체 반환 행을 쓴다.

재현은 이 커밋의 소스에서 실행한다. 각 JSON에 입력 SHA-256과 분석·정책 파일 SHA-256이 있다. 이후 정책을 바꾼 소스에서 실행하면 model-world 부분은 달라질 수 있다. 출력은 기존 파일을 덮어쓰지 않으므로 새로운 출력 폴더를 쓴다.

```powershell
$inputRoot = 'C:\dev\pq_afec_gen31\experiments\state'
$evidenceRoot = 'C:\dev\pq_afec_gen33\g3\v33\evidence'
$outputRoot = 'C:\dev\codex_handoff\v33\runs\a0_recheck'
foreach ($script in Get-ChildItem "$evidenceRoot\0*.py") {
    python -I -B $script.FullName --journal-root $inputRoot --out "$outputRoot\$($script.BaseName).json"
    if ($LASTEXITCODE -ne 0) { throw "A0 재현 실패: $($script.Name)" }
}
```

출처는 각 JSON의 source_scripts에 적었다. 원문 경로는 C:\dev\codex_handoff\v33\evidence 아래다. 전체 감사 처리 범위는 runs/A0_coverage.md에 기록한다.
