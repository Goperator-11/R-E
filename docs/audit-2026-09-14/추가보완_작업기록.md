# 연구 목적에 맞춘 추가 보완 기록

2026년 9월 14일 추가 검토. 정밀 측정은 계속 진행 중이다. 이 문서는 측정 중 수행한 오프라인 분석과 측정 종료 뒤 반영할 수정 항목을 구분한다.

이번 보완의 목적은 FEC와 패딩이 특정 QUIC 핸드셰이크 조건에서 지연을 줄이는지, 적응 정책이 고정 정책보다 유리한지 판단할 근거를 정리하는 것이다. 현재 측정의 소스, 실행 환경, 표본 수와 통과 기준은 바꾸지 않았다. 새 네트워크 실험이나 병렬 성능 측정도 시작하지 않았다.

추가 작업은 다음 자료에 담았다.

| 자료 | 추가한 내용 | 연구에서 쓰는 방법 |
|---|---|---|
| [표본 충분성](추가검토_표본충분성.md) | 완료된 p3 원자료로 p4의 판정불능 조건과 필요 표본 수 안내를 다시 계산 | 우열을 가리지 못한 조건을 결과에서 누락하지 않고, 추가 실험의 비용과 한계를 판단한다. |
| [정책 비교 설계](추가검토_정책비교_검증설계.md) | 정책 선택용 자료와 평가용 자료의 분리, 라틴 방격의 균형, 비교 시간창과 지표 정의 | 적응 정책의 이득을 확증할 후속 실험을 설계한다. 현재 자료의 사후 분석과 구분한다. |
| [연구 주장과 근거](추가검토_연구주장_근거표.md) | 연구 질문, 주장, 관측 지표, 실험 단계, 해석 한계의 대응표 | 본문·발표에서 각 결론을 실제 측정 근거와 연결한다. |
| [출처 점검 코드](추가검토_출처점검.py), [점검 결과](추가검토_출처점검.json) | 이번 실행의 완료 기록과 결과 SHA256 대조, 과거 성공 기록 제외, 수정 파일 사본 대조 | 과거 결과와 새 결과가 섞인 보고서를 막고, 점검에 사용한 바이트를 별도 보존한다. |

오후 4시 26분 33초 출처 점검에서는 선언된 25단계 중 14단계가 이번 실행의 완료 기록과 맞았다. 나머지 11단계는 이번 실행에서 아직 완료되지 않았거나 과거 상태만 있어 제외했다. 이 숫자는 실행 단계 수이며 독립 가설이나 실험 조건의 개수가 아니다. 이후 진행 상황은 원래 실행 로그와 후속 점검으로 확인해야 한다.

완료로 분류한 단계의 결과 파일은 실행기가 기록한 해시와 일치했다. 기존 수정 목록 54개에 대해 원본 위치와 두 Git 사본을 각각 확인한 162건의 대조에서도 불일치가 없었다. 일부 원본 위치는 Git 사본과 같은 경로이므로 162개의 서로 다른 파일을 검증했다는 뜻은 아니다. 이 대조는 수정 목록에 있는 파일을 대상으로 하며 시스템 전체나 모든 바이너리의 무결성 검사로 확대 해석하지 않는다.

출처 점검 도구는 실험 실행기를 import하지 않고 문법 트리에서 단계별 출력 파일 목록을 읽는다. 현재 성공, 과거 성공, 실패, 해시 누락, 파일 변조와 사본 불일치를 구분하는 회귀검사 9개를 통과했다. 이 9개는 기존 알고리즘 회귀검사 66개와 별도다. 검사 시 읽은 상태·결과 사본은 작업 폴더의 시각별 디렉터리에 보존했다. JSON에는 그 경로와 해시가 있다. 실행 프로세스의 환경을 다시 구성해 단계 지문을 독립 재계산한 검사는 아니다.

표본 충분성 요약기는 기존 필요 N 4개를 원자료에서 재현했고, 별도 검사 7개를 통과했다. 정책 비교에 쓰인 36,000시행의 성공 35,997건과 실패 3건도 따로 셌다. 재현에 필요한 원자료 사본·소스 사본·요약기·검사 파일은 [표본 충분성 재현 묶음](추가검토_표본충분성_재현.zip)에 있다.

추가로 확인한 문제와 후속 처리는 다음과 같다.

| 위치 | 확인한 문제 | 측정 종료 뒤 처리 |
|---|---|---|
| p4_model.py의 필요 표본 수 안내 | 실제 허용집합 판정에는 조건당 alpha=0.005를 쓰지만 안내 계산에는 1.96을 고정했다. 검정력 목표도 없다. | 기존 결과와 소스를 보존하고 안내 계산·출력 명칭을 고친다. alpha를 맞춘 정규근사도 확증 표본 수를 보장하지 않는다고 명시한다. 판정 기준은 완화하지 않는다. |
| p4 정책 일치 표현 | 6/6은 판정 가능한 조건에서 정책 선택이 현행 허용집합에 들어갔다는 뜻이다. 나머지 4조건은 판정불능이다. | 진짜 최적 정책을 증명했거나 동등성을 확인한 것처럼 표현하지 않는다. 사후 최선 선택과 부트스트랩 끝부분 추정의 한계도 유지한다. |
| p10_completeness.py의 기능 목록 | 폐루프의 ok 값과 "m은 사람이 준다"는 설명이 모순된다. m>=3 항목에도 오래된 설명이 있다. | 기능 구현 여부와 실측 검증 여부를 나누고 현재 소스·실행 근거에 따라 설명을 고친다. kind가 "시험"인 13/13 통과와 기능 목록의 미구현·제외 항목 수를 구분한다. |
| p11·p15·p17 비교 설계 | 사후 최선 정책 선택, 성공 표본 배열로 나눈 구간, 서로 다른 평가 시간창이 비교에 영향을 줄 수 있다. | 실제 시행 ID와 전체 균형 블록을 기준으로 비교한다. 현 자료의 민감도 분석과 독립 확증 실험을 구분한다. 상세 설계는 별도 문서에 따른다. |
| 하이브리드 규격 출처 | 앞선 정정안은 ECDHE-MLKEM 초안 -05를 인용했다. 해당 규격은 2026년 8월 RFC 10024로 발행되었다. | 정정안과 저장소 문서의 최신 규격 인용을 RFC 10024로 맞춘다. 기존 크기 정정의 수치 자체는 유지한다. |

X25519MLKEM768의 결합 공유비밀 64 B와 클라이언트 키 공유 1,216 B는 최종 규격에서도 확인된다. TLS가 이후 도출하는 키의 길이나 QUIC 전체 첫 비행 크기와는 다른 값이다. [RFC 10024 §4.1·§4.3](https://www.rfc-editor.org/rfc/rfc10024.html#section-4.3)

현재 수행한 추가 작업은 실행 정본과 두 Git 사본에 새 수정을 적용하지 않았다. 따라서 기존 수정 파일 수 54개와 코드 배포 묶음은 그대로다. 이번 문서와 별도 분석 도구는 추가 산출물이다. 측정 종료 후 후속 수정을 적용할 때 원자료 보존, 필요한 단계 재검증, 두 사본 동기화, 수정 목록과 보고서 갱신을 함께 수행한다.

현재 4조건의 판정불능이 재측정만 늘리면 반드시 해소되는 것은 아니다. 평균 차이가 작거나 실행 간 환경 차이가 남으면 표본 수 증가만으로 해결되지 않는다. 후속 확증 실험은 원래 연구 질문과 목표 지표를 먼저 고정한 뒤 결정한다.
