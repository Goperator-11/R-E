## 3. 가설을 바꾼 이유와 현재 연구 범위

초기 가설은 기존 Initial 패딩에 복구 정보를 넣으면 추가 송신 없이 원본 소거를 고칠 수 있다는 것이었다. 이 주장을 유지하려면 k와 W를 고정한 채 어떤 원본 데이터그램 하나를 잃어도 남은 정보가 복원에 충분해야 한다. 확인한 자연 비행은 용량 조건을 만족하지 않았다. 따라서 이 연구에서 시험한 설정의 무상 in-place FEC 주장은 철회한다.

현재 질문은 패딩과 별도 패리티에 필요한 추가 바이트를 지불하면서 어떤 조건에서 HCT를 줄일 수 있는가다. 비용은 최소한 송신 B/연결과 지연으로 각각 적는다. p3의 무손실 p50 추가 지연이 1 ms 미만이라는 검사 결과를 "공짜"라는 표현으로 바꾸지 않는다. 네트워크 바이트가 늘었는지, CPU 시간이 늘었는지는 별도 지표다.

FEC를 켜서 서버가 더 일찍 보낼 수 있게 된 효과와 실제 원본 소거를 복구한 효과도 분리한다. 무손실 패딩 비교는 전자를, 동일한 인증서·비행 설정의 지정 소거 대조는 후자를 시험한다. 두 효과를 혼합한 HCT 차이 하나만 제시하면 어느 메커니즘이 기여했는지 확인하기 어렵다.

## 4. RFC 규칙과 구현 모형을 쓰는 방법

규범적 한도는 검증 전 서버 송신량≤3×수신량이다. 반면 `A(B)=ceil(3B/P)·P`는 특정 구현의 패킷 단위 동작을 설명하려는 모형이다. 모형이 측정 경계를 맞추더라도 규칙을 바꾸지 않는다. 귀속 가능한 수신 데이터그램의 UDP 페이로드와 주소 검증 상태를 사용해 매 송신 시점을 검사해야 한다. 별도 FEC 패킷이나 합성한 스택 전달 바이트가 규칙상 신용에 해당하는지도 확인해야 한다. [RFC 9000 §8.1](https://www.rfc-editor.org/rfc/rfc9000.html#section-8.1)

p7 V11은 100 ms 간격의 L2 누계 관측이다. 이 사이에 발생한 순간 초과 송신이나 주소 검증 전후의 구분을 직접 판정하지 않는다. 보고서에서는 "관측 시점의 보조 계수 검사 통과"라고 적고 "RFC 준수 검증 완료"로 쓰지 않는다.

HCT의 꼬리 지표도 이름을 정확히 적는다. 현재 `padbed.summarize`의 `pto_rate`는 성공 연결 중 `HCT > RTT+500 ms`인 비율이다. 실제 PTO 타이머가 발화한 비율이 아니다. p8의 효과 판정은 `HCT > 1.5×RTT`인 비율의 차이를 사용한다. 이 두 값으로 PTO 횟수나 재전송 횟수를 대체하지 않는다. 실제 PTO 주장은 전송 계층 이벤트가 필요하다. [RFC 9002 §6.2](https://www.rfc-editor.org/rfc/rfc9002.html#section-6.2)

FEC를 사용할 때도 혼잡 제어와 추가 송신의 영향을 함께 보아야 한다. 현재 손실 모형에서 지연을 줄였다는 사실은 혼잡 신호를 보존하는지, 경쟁 흐름의 처리량을 떨어뜨리는지 답하지 않는다. [RFC 9265](https://www.rfc-editor.org/rfc/rfc9265.html)

## 5. 하이브리드 보안과 지연의 분리

최신 규격 인용은 RFC 10024를 사용한다. 이 규격은 2026년 8월 발행됐고 X25519MLKEM768 등의 결합을 정의한다. 하이브리드 키 교환은 구성 알고리즘 중 하나가 안전하게 남는 상황을 고려해 공유비밀을 결합한다. 그 보안 근거는 규격의 결합 구조와 전제에 있으며 HCT 비교에 있지 않다. X25519MLKEM768과 SecP256r1MLKEM768의 결합 공유비밀은 각각 64 B다. 이전 정정안의 -05 초안 인용은 수치 근거로 남길 수 있으나 최신 설명에는 발행된 RFC를 인용한다. [RFC 10024 §3, §4.3, §6](https://www.rfc-editor.org/rfc/rfc10024.html)

이 실험의 qamp는 자체 생성한 ECDSA 인증서와 `InsecureSkipVerify: true`를 사용하고 세션 재개를 끈다. 따라서 여기서 확인한 것은 제한한 키 교환·전체 핸드셰이크 조건의 동작과 지연이다. 실제 인증서 검증, PKI 인증, 양자 안전 서명 체인, 구현 인증까지 검증했다고 쓰지 않는다. 그룹 협상 성공이나 CRC 실패 0도 이 범위를 넓혀 주지 않는다.

다른 보안 속성을 갖는 키 교환 간 지연 비교와 같은 키 교환에서 전송 정책을 바꾼 비교는 목적이 다르다. FEC 성능을 주장할 때는 하이브리드 그룹을 유지한 off/on 비교를 중심에 놓고, X25519 비교는 크기와 패킷 배치에 따른 차이를 설명하는 별도 대조로 제시한다.

## 6. 보고서에 사용할 수 있는 조건부 결론

아래 문안은 이 추가 검토의 확인 범위 안에서 사용할 수 있다. 다른 실행이나 설정의 결과를 섞을 때는 조건과 수치를 다시 확인해야 한다.

1. "기존 패딩 안에 복구 정보를 배치하려던 초기 가설은 측정한 자연 비행 설정에서 용량 조건을 만족하지 않아 철회했다. 이후 실험은 패딩과 추가 패리티의 송신 비용을 포함해 지연 이득을 평가한다."

2. "9월 14일 두 하네스의 무손실 RTT 50 ms 비교에서는 인증서 크기에 따른 HCT 전환 구간이 일치했다. X25519는 3,312~3,368 B, X25519MLKEM768은 5,917~5,974 B였다. 이는 사용한 quic-go와 인증서·Initial 설정의 관측이다."

3. "9월 14일 하이브리드 그룹의 지정 소거 시험에서 m=1 FEC는 원본 하나의 소거를 복구했다. 패리티를 함께 제거하거나 두 원본을 소거한 음성 대조에서는 같은 복구 이득이 나타나지 않았다. 이 결과는 시험한 단일 소거 복구 경로를 뒷받침한다."

4. "RTT 50 ms, 인증서 설정 2,955 B, 클라이언트→서버 손실 2%, 하이브리드 그룹의 3라운드에서 각 팔 600개 성공 지연 표본을 합쳤다. HCT가 75 ms를 넘는 비율의 on1−off 차이는 약 -4.17%p였고, 연결 표본 부트스트랩 구간은 [-5.83, -2.67]%p였다. 이 구간은 해당 재추출 방법에 따른 것으로 시간 상관과 실행 순서의 영향까지 제거하지 않는다."

5. "HCT 모형의 해당 평가 오차는 MAE 약 3.80 ms였다. 임계 예측은 8개 중 7개가 측정 구간 안에 들었다. 정책 비교에서 판정 가능한 6조건의 선택은 현행 규칙에서 관측 최선과 차이를 구별하지 못한 허용집합에 속했으며, 나머지 4조건은 판정 불능으로 남았다. 이 판정은 동등성을 검증한 결과가 아니다."

6. "정해진 오류·동시 연결 시험은 통과했으나, RFC 증폭 제한의 모든 송신 시점 검증, 혼잡 공정성, CPU 비용, 실제 무선망·다른 QUIC 구현은 이 결과만으로 확인하지 않았다. 적응 정책 전체의 결론은 진행 중인 후속 정밀 단계와 독립 평가를 마친 뒤 제시한다."

p8은 라운드마다 off 다음 on을 실행하고 연결 표본을 합쳐 부트스트랩한다. 따라서 문안 4의 구간을 무작위 교차 배치·블록 단위 재추출의 결과라고 설명하지 않는다. p3의 개별 p99 차이도 별도 신뢰구간 없이 모든 조건의 유의한 개선으로 묶지 않는다. p4는 같은 자료에서 보정·모형 선택에 영향을 받은 부분과 독립 예측 부분을 표시해야 하며, 전체 외부 검증의 대체물이 아니다.

## 7. 아직 답하지 못한 질문을 검증 가능한 형태로 남기기

| 남은 질문 | 추가 근거가 갖춰야 할 조건 | 현재 사용할 표현 |
|---|---|---|
| 적응 정책이 정적 정책보다 유리한가? | 보정·학습과 분리한 조건, 같은 정보 제약, 블록별 실행, 사전 정의한 regret와 CI 기준, 실패·콜드스타트 포함 | 후속 정밀 단계 진행 중. 현재 p4만으로 전체 우월성은 결론 내리지 않음 |
| 증폭 제한을 준수하는가? | 연결별 UDP 페이로드와 검증 시각을 식별한 전 송신 추적, FEC·합성 패딩의 회계 근거 | 보조 계수 검사 통과. 규범적 준수의 직접 검증은 남음 |
| 합성 버스트를 넘어 실제 망에서도 유효한가? | 실제 손실 연속 길이·방향·비정상성을 기록한 독립 자료, 학습에 쓰지 않은 경로, 환경별 결과 | 평균 버스트 길이 3의 netem 조건을 포함해 측정. 실망 일반성은 미검증 |
| 혼잡에서 더 나은가? | 병목과 경쟁 흐름, 지연·goodput·송신량·혼잡 신호를 함께 비교 | 손실 복구 효과만 확인. 혼잡 공정성은 미측정 |
| 계산 비용이 작거나 줄어드는가? | 완료 연결당 CPU·메모리·부호화·정책 비용, 동일 부하와 설정의 대조 | 짧은 HCT 추가 지연을 관측했으나 CPU·서버 부하 절감은 미측정 |
| 암호학적으로 안전한 구현인가? | 규격의 입력·키 검사와 인증 경로, 별도의 보안 분석·시험 범위, 인증서 검증을 포함한 상호운용 | 협상 그룹과 지정 오류 처리를 확인. 안전성 증명·제품 인증은 수행하지 않음 |

이 표는 새 실험을 실행하거나 완료 판정을 바꾸기 위한 지시가 아니다. 진행 중인 정밀 측정 이후에도 남는 질문을 제출문에서 검증 가능하게 표현하려는 기준이다.

## 8. 원문을 읽은 범위와 남긴 한계

기존 정정안에서 기록한 문서 31종과 원자료 대조 범위를 유지한다. 이번 추가 작업에서는 p3·p4·p7·p8·p9·p10 결과, 대응 실행 소스의 측정·판정 부분, `padbed`의 지표 정의, qamp의 인증서·TLS 설정, `loop2` 완료 기록과 로그를 읽었다. 소스 전부를 새로 감사하거나 보안 시험을 반복한 것은 아니다.

규격 근거는 앞서 확인한 RFC 9000·9002와 이번에 다시 확인한 RFC 9265·RFC 10024를 사용했다. Sakk 출판사 원문 접근 실패와 기존 선행연구의 전체 본문 미확인 한계는 해소되지 않았다. 새 문헌의 수를 늘려 연구 신규성 검증을 완료했다고 주장하지 않는다.
