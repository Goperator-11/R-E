# 실험 환경 대조

`실험환경_명세서.docx`(2026-08-19, 교내 연구 서버 kebap-server)를 이 기계에서
재현한 결과다. **같은 것과 다른 것을 나눠 적는다** — 다른 것을 숨기면 결과를
인용할 때 어디까지 옮겨도 되는지 알 수 없다.

### 이번에 맞춘 두 가지

명세 §5 통제변수인데 테스트베드에 빠져 있었다.

1. **세션 재개 차단** — 서버 `tls.Config` 에 `SessionTicketsDisabled: true`.
   재개 자체보다도, 티켓을 발급하면 `NewSessionTicket` 이 서버 비행 뒤에 붙어
   `server_bytes` 를 부풀린다. **s0 추정에 직접 섞이는 잡음**이었다.
2. **Path MTU Discovery 비활성** — 양쪽 `quic.Config` 에
   `DisablePathMTUDiscovery: true`. 켜 두면 연결 도중 MTU 탐침이 나가
   데이터그램 크기가 변하고 증폭 회계가 오염된다.

효과가 실측으로 보인다. 절벽 실험의 `ips=1281` 에서 예전에 2-RTT 비율
**0.025** 짜리 이상치가 있었는데(당시 "40 회 중 1 회 잡음"으로 남겨 뒀다),
이번엔 두 그룹 모두 **정확히 0.000** 이다.

| 반복 수 | QUIC 손실 스윕 조건당 2,000 | 조건당 200 (워밍업 20 제외) | **평균의 표준오차가 커진다.** 손실 실험 해석에 반영 |
| 버스트 파라미터 | `loss gemodel 5% 50%` (문자 그대로) | `gemodel 2.63% 50%` | 아래 참고 |

### 버스트 파라미터를 문자 그대로 쓰지 않은 이유

명세 §4-3 은 `netem loss gemodel 5% 50%` 라고 적고, 본문은 그 뜻을
**"전이확률 50%, 평균 버스트 길이 2"** 라고 설명한다. 그런데 netem 의
`gemodel p r` 에서 `p` 는 Good->Bad 전이확률이고 정상상태 손실률은
`p/(p+r)` 다. 문자 그대로 넣으면 손실률이 `0.05/0.55 = 9.1%` 가 되어
**"손실 5%" 라는 독립변수가 무너진다.**

그래서 `padbed._netem_spec` 은 목표 손실률을 고정한 채 역산한다:
`r = 1/L`, `p = r·loss/(100−loss)`. 손실 5%·평균버스트 2 면
`gemodel 2.63% 50%` 이고 정상상태 손실률이 정확히 5% 다.
**명세의 문자가 아니라 명세의 의도를 따랐다.**
