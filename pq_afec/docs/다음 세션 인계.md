## 3. 알고리즘 핵심 (v0.1에서 변한 것 없음)

```
    J(r) = (1 + β·g) · t_tx(r)  +  P_fail(K, r) · T_recover
    r*   = argmin_r J(r)
```

**`T_recover`만 갈아끼우면 핸드셰이크 모드(PTO≈999ms)와 데이터 모드(2·RTT)가
같은 식에서 나온다.** 연구의 축: ML-KEM 키 공유 1216B > Initial 1200B →
ClientHello 강제 분할 → 조각 1개 손실 = 약 1초 정지. (명세 v0.1 §2)

### v0.2가 얹은 것 — 목적지별 통계 캐시 (`afec/cache.py`)

- **키 = (접속망 ID, 목적지 /24)**. 접속망이 키의 절반이라 Wi-Fi↔셀룰러 이동
  무효화가 공짜(키가 달라져 옛 항목을 아예 안 읽음). SNI는 버렸다(경로가 아님).
- 폴백: 정확 항목 → 망 집계 `(망, *)` → 기본값.
- **사전값은 시작점(p, burst)과 확신도(n_eff)만 주고, 추정 관성은 안 바꾼다.**
- **반출 가중치 상한 100** + **risk_z 2.5→1.5** — "캐시가 어떻게 틀려도
  콜드보다 나쁘지 않다"의 성립 조건 (유일해였다. 명세 v0.2 §5).
- 결과: 짧은 연결(30블록) 최악 후회 콜드 33.5% → 캐시 정확 시 **7.7%**,
  틀린 캐시 전 시나리오 ≤ 콜드. 긴 연결도 6.8%→6.3%로 소폭 개선.

## 6. 이미 밟은 지뢰 (다시 밟지 말 것)

v0.1 목록(명세 v0.1 §12 + 이전 인계)에 더해 v0.2에서 추가된 것:

1. 🩸 **포기 붕괴**: argmin J는 p에 단조가 아니다. 상한점이 "가망 없음" 능선을
   넘으면 r*=0으로 무너져 보호가 꺼진다. → 상한은 보호를 늘리는 방향으로만.
   (비단조 결정 문제에 단측 신뢰상한을 점추정처럼 꽂으면 안 된다)
2. 🩸 **사전 가중치를 EWMA 질량에 넣으면 안 된다**: 틀린 캐시에서 벗어나는
   속도가 w배 느려진다. w는 확신(n_eff→se)에만. 추적 관성은 캐시 신뢰와 무관.
3. 🩸 **z와 캐시 가중치는 같은 것(초반 조심성)의 두 손잡이 — 반드시 공동 튜닝.**
   따로 하면 v0.1의 n_eff 사건(파라미터가 남의 역할 떠맡기)을 반복한다.
4. **확신에 찬 캐시는 초반 헤지를 깎는 게 정의다.** "많이 믿기"와 "틀릴 때 안전"은
   양립 불가 → 반출 상한이 유일한 손잡이. 캐시의 값어치는 확신이 아니라 시작점.
5. 🩸 Windows에서 긴 계산을 숨김/백그라운드로 돌리면 효율 모드 스로틀(4배 느림).
   조각내서 포그라운드로. 관찰 도구도 조심: Git Bash ps는 네이티브 프로세스를
   못 보고, 쓰는 중인 파일은 PowerShell로 읽어야 최신이다.
6. 시드 12개 미만 결과로 순위 주장하지 말 것 — v0.1 헤드라인("정적>콜드")이
   시드 8개 잡음이었고, "버스트 −5.5% 잔여 편향"도 시드 1개 잡음(유령)이었다.
7. 🩸 **데이터가 고른 표본에 데이터 의존 가중치를 주지 말 것** (v0.2.1 결함 13).
   놀라운 블록에만 jump_alpha를 주면 관측치가 자기 극단성으로 가중돼 추정이
   +10% 위로 표류한다. 부스트는 **확정 이후 블록**(새 국면의 공정한 표본)에만.
   하향 변화는 블록 하나로는 원리적으로 못 잡는다(소실 분포 바닥이 0에 붙음)
   → 누적 로그우도비(SPRT, down_h=3.0)로 판정한다.
