## 3. 절대 어기면 안 되는 것 (전부 한 번씩 사고를 냈다)

1. **측정 중에 소스를 고치지 마라.** 저널 지문은 파일 **날바이트 SHA** 다.
   한 글자만 고쳐도 몇 시간치 측정이 무효가 된다.
2. **측정을 겹쳐 돌리지 마라.** 전례가 파일 이름에 남아 있다 —
   `p15_units.오염_겹쳐돌아_20260826_1655.jsonl`. `fixloop.lock` 이 막지만
   손으로 우회하지 마라.
3. **WSL 로 환경변수를 넘길 때는 `WSLENV` 이 필요하다.** `wsl.exe` 는
   부모 환경을 **안 물려준다.** 2026-08-28 에 발견 — 그전까지 문서에 적힌
   정밀도 실행 명령은 **N 을 전혀 올리지 못하고 평범하게 돌고 있었다.**
   지금은 `loop2.py` 가 `PADFEC_*` 를 자동으로 태워 보내므로 위 명령은
   그냥 쓰면 된다. **다만 `wsl` 을 손으로 부를 때는 직접 줘야 한다:**
   `WSLENV=PADFEC_P11_N PADFEC_P11_N=4000 wsl -d Ubuntu -- ...`
   → `04 하우투\PAD-FEC 실험 돌리기 (WSL 배포판 함정)`
4. **WSL 배포판은 `-d Ubuntu`.** 이 PC 의 기본은 `kali-linux` 이고
   거기엔 Go 도 quic-go 도 없다.
5. **증폭 불변식을 깨지 마라.**
   `BytesToStack + pendingBytes + len(rec) <= BytesIn`.
   이게 깨지면 심이 RFC 9000 §8.1 의 3 배 제한을 **우회하는 것**이고,
   그러면 측정 전부가 무의미해진다.
6. **개인키를 저장소에 두지 마라.** `experiments/pki/**/*.key` 는
   `.gitignore` 에 있다. 하네스가 필요할 때 다시 만든다.

## 4. 2026-08-27~28 에 바뀐 것 (가장 최근)

친구(신레오)가 우리 알고리즘으로 교차검증을 했고 `recoverOne` 이
**소거를 하나만** 받는다는 것을 찾아 줬다(보고서 정확했다). 그래서:

- **2 단계 = 다중 소거 복구.** 선행 패리티는 **신용 전용**, 뒤따르는
  m−1 개가 **복구 무리**. 보류는 소거가 2 개 이상일 때만 → 흔한 경우
  신용을 그대로 낸다. `k=2 p=0.15` 에서 `P_fail 0.06075 → 0.01198` (5.1 배).
  **m≤2 는 비트 단위로 불변** — 기존 실측이 안 흔들린다.
- **차단 결함 2 건 수리** (`qamp.go`): 회계 순서(신용 +1280 B 부풀림) ·
  심볼 버퍼 별칭(`sync.Pool` 재사용). **둘은 같이 고쳐야 한다** —
  별칭이 회계 결함을 가리는 우연한 안전망이었다.
- 자체시험 33 → 195. 돌연변이로 각각 붉어지는 것 확인.

### 한계로 적어 둔 것 (자랑이 아니다)

- **2 단계는 버스트에서 약하다.** `k=2 m=3` 이 버스트 1 에서 5.1 배지만
  버스트 3 에서는 **1.4 배**. 비행 배치가 `[P,O,O,P,P]` 라 복구 패리티가
  꼬리에 몰려 있고 버스트는 인접한 것을 함께 지운다. **구조적 한계다**
  (복구 패리티는 소거 개수가 확정된 뒤에 와야 하므로 원본 사이에 못 낀다).
  시간 간격을 벌리는 완화책은 **일부러 안 썼다** — 우리 GE 모형은 손실을
  패킷 색인으로 다루므로 그 수정은 **모형 인공물을 최적화하는 것**이 된다.
- **버스트 축은 최근접 스냅이다** (`idxNearestF`, 격자 `{1,2,3,5}`).
  p 축만 선형보간한다. 격자 밖 640 점 중 13 건(2.0%)에서 결정이 갈리고
  후회는 최악 1.528 ms. **지금은 대가가 0** — 버스트 추정기가 없어
  항상 `defaultAssumedBurst = 1`(격자 위 점)이기 때문이다.
  관문 격자도 버스트를 `{1,2,3}` 으로만 돌아 이 오차를 **원리적으로 못 본다.**
