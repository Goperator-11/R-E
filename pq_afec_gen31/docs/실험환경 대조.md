# 실험 환경 대조

`실험환경_명세서.docx`(2026-08-19, 교내 연구 서버 kebap-server)를 이 기계에서
재현한 결과다. 명세와 같은 것과 다른 것을 나눠 적었다. 다른 점을 적어 두지 않으면
결과를 인용할 때 어디까지 옮겨도 되는지 알 수 없기 때문이다.

### 이번에 맞춘 두 가지

둘 다 명세 §5의 통제변수인데 테스트베드에 빠져 있었다.

1. 세션 재개 차단. 서버 `tls.Config`에 `SessionTicketsDisabled: true`를 넣었다.
   재개 자체보다, 티켓을 발급하면 `NewSessionTicket`이 서버 비행 뒤에 붙어
   `server_bytes`를 부풀리는 것이 문제였다. s0 추정에 직접 섞이는 잡음이었다.
2. Path MTU Discovery 비활성. 양쪽 `quic.Config`에
   `DisablePathMTUDiscovery: true`를 넣었다. 켜 두면 연결 도중 MTU 탐침이 나가
   데이터그램 크기가 바뀌고 증폭 회계가 오염된다.

효과는 실측에서 보인다. 절벽 실험의 `ips=1281`에서 예전에는 2-RTT 비율
0.025짜리 이상치가 있었는데(당시 "40회 중 1회 잡음"으로 남겨 뒀다),
이번에는 두 그룹 모두 정확히 0.000이다.

### 버스트 파라미터를 문자 그대로 쓰지 않은 이유

명세 §4-3은 `netem loss gemodel 5% 50%`라고 적고, 본문은 그 뜻을
"전이확률 50%, 평균 버스트 길이 2"라고 설명한다. 그런데 netem의
`gemodel p r`에서 `p`는 Good->Bad 전이확률이고 정상상태 손실률은
`p/(p+r)`다. 문자 그대로 넣으면 손실률이 `0.05/0.55 = 9.1%`가 되어
"손실 5%"라는 독립변수가 성립하지 않는다.

그래서 `padbed._netem_spec`은 목표 손실률을 고정한 채 역산한다.
`r = 1/L`, `p = r·loss/(100−loss)`이므로 손실 5%·평균 버스트 2면
`gemodel 2.63% 50%`가 되고, 정상상태 손실률이 정확히 5%다.
명세에 적힌 숫자보다 명세가 설명한 의도를 따른 것이다.

```bash
# 환경만 세우고 확인
experiments/quicbed/netbed_spec.sh 50 0 'ping -c 4 -q 10.9.0.2'

# 빌드 (명세 8절 함정: CGO_ENABLED=0, /tmp 로 복사)
GOTOOLCHAIN=go1.26.5 experiments/quicbed/build.sh

# 탐침
unshare -Urnm python3 experiments/_probe_cliff.py x25519 4032 40
unshare -Urnm python3 experiments/_probe_trecover_rtt.py
```
