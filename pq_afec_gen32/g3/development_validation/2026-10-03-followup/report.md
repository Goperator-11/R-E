# 학술 동아리 알고리즘 추가 개선 기록

2026년 10월 3일, PAD-FEC `v3.2-dev`의 후속 수정이다. 첫 개발 커밋 `d3a9764f75ac6b7e2a1891f4154ed806bc8017ec` 이후 후보 생성, 학습·캐시 상태 보존과 빌더를 보완하고 합성 적응 벤치를 추가했다. 개발 사본은 `C:\dev\pq_afec_gen32`이며 v3.1 측정 원본은 수정하지 않았다.

## 수정한 코드

`padfec3/decide3.py`에서 자동 후보가 `m_max`를 넘지 않도록 했다. 기존에는 `m_max=0`이어도 패리티 후보가 나왔고 큰 `max_steps`에서 지원 범위를 벗어난 후보가 만들어졌다. 생성 옵션을 먼저 검사하고, 양수 `max_ips` 경로에서는 패딩 크기와 패리티 개수의 상한을 넘는 단계를 계산하지 않는다. `max_ips=None/0`의 무제한 분석 모드와 raw `levers_s`는 여전히 `max_steps`에 비례해 계산한다. 명시적인 `actions`는 분석·재생용 후보 목록으로 남겨 생성 옵션을 적용하지 않는다.

`padfec3/learn3.py`의 관측 처리는 복제 상태에서 계산한 뒤 성공했을 때 반영한다. 잘못된 `later`, 잔차 차이의 오버플로, 전이 기준값이나 우도 계산 오류가 나면 호출 전 상태를 유지한다. 비용 모형 캐시는 100,000개 계산 점까지 보관하고 FIFO로 제거한다. 제거한 점은 다시 계산하며 비용과 결정이 달라지지 않는지 검사했다. 이는 항목 수 제한이며 메모리 바이트 수 제한은 아니다.

`experiments/quicbed/policy3.go`도 목적지 캐시의 결정과 관측을 성공했을 때 반영한다. 이전에는 잘못된 입력으로 관측에 실패해도 최소 RTT·HCT와 카운터가 바뀔 수 있었다. 목적지 메타데이터를 검사하고, 캐시 JSON 문서 뒤의 추가 문서나 쓰레기 데이터는 거부한다. 문서 뒤의 공백은 허용한다. 저장할 때도 잘못된 상태를 거부한다.

`experiments/quicbed/build_gen32.sh`는 매번 새 작업 폴더에서 빌드한다. 소스에서 삭제한 예전 검사 파일이 다음 빌드에 섞이는 문제를 막았다. `--race`는 같은 작업 폴더의 소스로 실행한다. 임시 컴파일러를 쓰는 별도 검사는 반복 빌드의 소스 격리와 정리, 잘못된 옵션의 조기 거부를 확인한다.

캐시 저장 임시 파일과 최종 빌드 출력에는 실행 간 잠금이 없다. 캐시는 한 프로세스에서 사용하고 빌더는 단독 실행하는 현재 흐름을 지원한다. Python 관측 성공 시에는 내부 list와 dict를 교체하므로 호출 전에 잡아 둔 내부 객체 참조를 계속 읽는 방식은 지원하지 않는다. 현재 호출부는 상태 객체를 통해 값을 읽는다.

## 검증 결과

Python 회귀검사 109개와 하위 검사 367개, Go 검사 101개가 통과했다. Go vet, race 검사와 빌드도 통과했다. WSL 빌더 격리 검사 2개가 통과했다.

Go·Python 교차 검증은 기준 원시 모형 2,800개와 결정 6,720개, 추가 난수 모형 2,600개와 결정 5,000개에서 통과했다. 10,000단계 궤적 아홉 개의 선택 결과와 학습·감시 상태가 모두 정확히 일치했다. 계산 비용 차이는 0이었다. 바이너리와 기준 자료의 소스 지문도 현재 코드와 일치한다. 이는 두 구현의 일치 검사이며 실제 네트워크 성능이나 예측 정확도의 증거는 아니다.

과거 저널 1,000행의 개발 재생에서 관측 1,000회, 위험률 예측 전이 1,000회, 우도 갱신 769회를 확인했다. 새 결정은 실제 연결에 실행하지 않았다. v3.1 봉인 소스 31개와 결과·저널·봉인을 포함한 보호 파일 88개의 해시가 모두 그대로다.

## 추가한 합성 적응 벤치

`experiments/adaptation_benchmark.py`는 정책의 비용 모형으로 결과를 만드는 개발용 벤치다. 조건 3개와 시드 31·32·33에서 공통 준비 상태를 복제한 뒤 각 비교군을 480단계씩 실행했다. `full`, 손실 사후분포를 고정한 `frozen_loss`, 학습을 건너뛴 관측의 위험률 전이만 막은 `skip_hazard_ablation`을 비교한다. 관측 이력과 감시 상태는 모든 비교군에서 계속 진행한다.

원본 패킷·패리티 패킷·경주에 같은 난수를 대응시켜 비교한다. 참 손실률의 기대 비용과 공통 후보의 최소 기대 비용 차이를 계산하고, 한 번 뽑힌 합성 비용과 구분한다. 비교 관측은 총 12,960행이다. 준비 비용은 비교에서 제외했다. 입력·적용 프로토콜, 소스와 잡음 테이프의 해시도 저장했다.

조건 안의 `k`, 서버 바이트와 RTT는 고정하고 패킷 손실은 독립이라고 가정한다. 첫 비행 실패에는 실제 재시도 궤적 대신 평균 회복 비용을 쓴다. `frozen_loss`는 전체 적응을 끈 비교군이 아니며, oracle도 공통 후보 집합 안의 최소값이다.

아래 값은 시드 세 개에서 얻은 평균 기대 비용 차이의 범위다. 단위는 ms이고 각 값은 비교군 비용에서 `full` 비용을 뺀 값이다. 양수이면 해당 모형에서 `full` 비용이 더 작고, 음수이면 더 크다.

| 합성 조건 | `frozen_loss` 차이 | `skip_hazard_ablation` 차이 |
|---|---:|---:|
| 큰 인증서, 손실 상승·회복 | 5.190846 ~ 10.478644 | -1.141114 ~ 4.200533 |
| 인증서 6,000 B, 손실 상승·회복 | 0 | 0 |
| RTT 200 ms, 일정한 손실률 | 0.062831 ~ 0.324208 | 0 |

큰 인증서의 시드 33에서는 위험률 전이를 막은 비교군이 `full`보다 기대 비용이 1.141114 ms 작았다. 같은 조건의 높은 손실 구간이나 회복 구간도 따로 확인해야 한다. RTT 200 ms의 시드 31에서는 기대 비용 차이가 +0.062831 ms인데 뽑힌 합성 비용 차이는 -0.588467 ms였다. 기대값과 한 번 뽑힌 결과의 방향도 같지 않을 수 있다. 차이가 없는 조건과 불리한 시드를 함께 남긴다.

이 결과는 정책 자신의 비용 모형 안에서 얻은 기술 통계다. 검정이나 신뢰구간을 계산하지 않았고 실제 HCT나 네트워크를 측정하지 않았다. v3.1의 H1 통과, H2·H3 실패와 H4 적응 기여 미확인 판정은 원래 측정의 판정으로 남는다. 새 코드의 실측 성능과 적응 기여는 아직 확인하지 않았다.
